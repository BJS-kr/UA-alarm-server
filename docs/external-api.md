# 외부 발송 API (mock) 계약 요약

연동 대상 외부 서버(`ghcr.io/us-all/backend-assignment-api:1.2`, 포트 `4000`)의 API 명세와 실측 동작 요약이다. 상세 측정 수치는 [mock-observations.md](./mock-observations.md)에 기록되어 있다.

## 사용 엔드포인트

| 용도             | 요청                                                          | 성공 응답                                                                                          |
| ---------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 사용자 목록 조회 | `GET /v1/users?cursor=&limit=`                                | `200 { users: [{ id, ... }], nextCursor }` (마지막 페이지 시 `nextCursor: null`)                   |
| 메시지 발송      | `POST /v1/messages { alarmId, recipientId, body, clientRef }` | `202 { messageId }`                                                                                |
| 발송 내역 조회   | `GET /v1/messages?clientRef=`                                 | `200 { messages: [{ messageId, recipientId, sentAt }] }` (동일 `clientRef` 중복 발송 건 전체 반환) |
| 헬스체크         | `GET /health`                                                 | `200` (Docker Compose 기동 순서 제어에만 사용, ADR-0014)                                           |

- 메시지 발송 요청 스키마에는 제목(`title`) 필드가 없으므로 본문(`body`)만 전송한다(ADR-0021).
- 메시지 발송은 단일 수신자 단위로만 호출 가능하다.
- 사용자 목록 조회의 `cursor`는 불투명(opaque) 문자열로 취급한다(ADR-0006).

## 응답 코드별 외부 기록 여부 및 처리 방식

오류 응답 본문은 `{ code, message }` 형식이다.

| 응답                                         | 외부 메시지 기록 생성 여부 | 워커 처리 방식                                                          |
| -------------------------------------------- | -------------------------- | ----------------------------------------------------------------------- |
| `202 Accepted`                               | 생성됨                     | `SENT` 확정                                                             |
| `400 Bad Request` (`RECIPIENT_BLOCKED` 등)   | 생성되지 않음              | 영구 실패(`FAILED`) 확정 (재시도하지 않음)                              |
| `429 Too Many Requests` (`Retry-After` 포함) | 생성되지 않음              | 공유 토큰 버킷 `paused_until` 갱신 후 `PENDING` 복귀 (시도 횟수 미차감) |
| `500`, `503`                                 | 생성되지 않음              | 지수 백오프 후 재시도 (`PENDING`)                                       |
| 응답 타임아웃 또는 소켓 연결 끊김            | 요청 접수 시 즉시 생성됨   | `UNCONFIRMED` 전환 후 발송 내역 조회(`Reconciliation`)로 확정(ADR-0002) |

## 주요 동작 특성 (실측 요약)

- **처리량 제한**: `POST /v1/messages`에만 적용되며 용량 50, 초당 50개 충전되는 토큰 버킷으로 동작한다. `429`로 거절된 요청은 토큰을 소모하지 않는다.
- **응답 분포**: 기본 설정에서 400건 발송 시 `202` 93.8%, `500` 3.8%, `503` 1.8%, `400` 0.75% 비율을 보였다.
- **응답 지연**: p50 64ms, p95 3.2초, p99 30초. 지연 응답은 3.0~4.5초 구간에 분포하며, 타임아웃 유도 요청은 정확히 30초(`TIMEOUT_MS`) 후 응답한다.
- **기록 시점**: 지연 응답이나 타임아웃 유도 요청도 서버 접수 즉시 발송 내역에 기록되며, 클라이언트가 먼저 연결을 종료해도 기록이 유지된다.
- **비멱등성**: 동일 `clientRef`로 두 번 요청하면 두 건 모두 발송 및 기록된다(ADR-0002, 0004).
- **평가용 집계 엔드포인트**: 컨테이너 환경변수 `ADMIN=1` 설정 시 `GET /_admin/stats?alarmId=`를 통해 알림별 수신자 수, 중복 수신자 수, 누락 수신자 수를 조회할 수 있으며 E2E 테스트 검증에 사용한다.
