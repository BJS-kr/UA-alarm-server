# ADR-0036. pg 드라이버 기반 Drizzle ORM 도입 및 조건부 UPDATE 전용 쓰기 규칙

## 배경

본 시스템의 정확성은 조건부 상태 전이, `FOR UPDATE SKIP LOCKED`, 행 잠금 등 SQL 문장에 의존한다. 또한 ORM이 조회한 엔티티 전체를 다시 저장하는 방식(entity save)을 사용하면, 조회와 저장 사이에 다른 워커가 변경한 값을 덮어쓰는 갱신 손실(lost update)이 발생한다.

## 결정

- **쿼리는 Drizzle 빌더로 작성한다.** `sql` 템플릿(SQL을 문자열로 직접 작성하는 방식)은 빌더로 표현할 수 없는 곳에만 사용한다. 현재는 단일 문장으로 계산과 차감을 수행해야 하는 토큰 버킷 쿼리(ADR-0009)와, 빌더 내부의 값 위치에 넣는 작은 표현식(DB 시계 `clock_timestamp()`, `nextval`, `attempts + 1`, `GREATEST(...)`, `'-infinity'` 등)뿐이다.
- **SQL은 저장소 파일(`*.repository.ts`) 내부에만 둔다.** 서비스와 워커 루프처럼 처리 흐름을 담당하는 코드는 저장소 메서드만 호출하며 SQL을 직접 작성하지 않는다.
- **모든 쓰기는 조건을 명시한 SQL 문장으로 작성한다**(ADR-0016의 조건부 `UPDATE`). 조회한 엔티티를 통째로 저장하는 방식은 사용하지 않는다.
- 상태와 종류 컬럼에는 `$type`으로 도메인 타입을 지정하여 조회 시 별도 형변환을 하지 않는다. DDL은 변경되지 않는다.
- Drizzle은 `pg`(`node-postgres`) 드라이버 위에서 동작한다. 커넥션 풀의 세션 설정(트랜잭션 유휴 한도, ADR-0004)은 `pg` 풀 옵션으로 설정한다.
- 마이그레이션은 `drizzle-kit`이 스키마 변경을 SQL 파일로 생성하고, `migrate` 서비스(ADR-0025)가 Drizzle 마이그레이터로 적용한다. 생성된 SQL을 그대로 검토하며, DB 계정과 권한은 PostgreSQL 초기화 스크립트에서 생성한다.
- 의존성: `drizzle-orm`, 개발 의존성 `drizzle-kit`.

## 근거

- 핵심 쿼리(조건부 상태 전이, `FOR UPDATE SKIP LOCKED`, 알림 행 잠금과 `NOT EXISTS`, 토큰 버킷, `RETURNING`, 부분 인덱스)를 모두 표현할 수 있다. 복잡한 구간도 동일한 방식(`sql` 템플릿) 안에서 해결되어 쿼리 작성 방식이 하나로 유지된다.
- 스키마 정의에서 타입이 자동으로 추론된다.
- 조회 후 전체 행을 덮어쓰는 동작(unit of work)이 없어 동시성 환경에서 갱신 손실(lost update) 위험이 없다.
- 빌더 구조가 SQL과 직관적으로 대응하여, ADR의 쿼리 명세와 대조하고 결함 주입 목록(ADR-0034)에서 특정 구문을 지정하기에 적합하다.

## 검토한 대안

- **TypeORM**: NestJS에서 가장 널리 쓰이지만 핵심 쿼리는 raw SQL로 작성해야 하므로 쿼리 작성 방식이 둘로 갈린다. 또한 `save()`가 조회한 엔티티를 통째로 덮어써서 워커가 그 사이에 변경한 상태를 유실시키는 갱신 손실(lost update)이 발생할 수 있다.
- **Prisma + TypedSQL**: SQL 파일에서 타입이 지정된 함수를 생성할 수 있으나 코드 생성과 드라이버 어댑터 등 중간 단계가 많고, 일반 CRUD와 핵심 쿼리의 작성 방식이 분리된다.
- **`pg` 드라이버로 SQL 직접 작성**: 가장 가볍고 SQL이 그대로 드러나지만, 결과 타입을 직접 선언하고 마이그레이션 실행기를 직접 구현해야 한다.
- **Kysely**: Drizzle과 유사한 절충안이나, 스키마 정의에서 마이그레이션 SQL 생성 도구까지 일체형으로 제공하는 Drizzle을 선택했다.
