# ADR-0036. DB 접근은 Drizzle(`pg` 드라이버 위)로 하고, 모든 쓰기는 조건을 적은 문장으로 한다

## 결정

- **쿼리는 Drizzle 빌더로 쓴다.** `sql` 템플릿은 빌더로 나타낼 수 없는 곳에만 쓴다. 지금은 문장 하나(계산과 지급이 한 문장이어야 하는 토큰 버킷, ADR-0009)와, 빌더 안의 값 자리에 넣는 작은 식(DB 시계 `clock_timestamp()`, `nextval`, `attempts + 1`, `GREATEST(...)`, `'-infinity'` 등)뿐이다.
- **SQL은 저장소(`*.repository.ts`) 안에만 둔다.** 서비스와 워커 루프처럼 흐름을 나타내는 코드는 저장소의 메서드만 부르고 SQL을 직접 쓰지 않는다.
- **모든 쓰기는 조건을 적은 문장으로 쓴다**(ADR-0016의 조건부 UPDATE). 읽은 엔티티를 통째로 저장하는 방식은 쓰지 않는다.
- 상태와 종류 컬럼은 `$type`으로 도메인 타입을 붙여, 읽은 값을 형변환하지 않는다. DDL은 바뀌지 않는다.
- Drizzle은 `pg`(node-postgres) 드라이버 위에서 돈다. 연결 풀의 세션 설정(트랜잭션 유휴 한도, ADR-0004)은 `pg` 풀 옵션으로 건다.
- 마이그레이션은 drizzle-kit이 스키마 변경을 SQL 파일로 만들고, migrate 서비스(ADR-0025)가 Drizzle의 마이그레이터로 적용한다. 만들어진 SQL을 그대로 검토한다. DB 계정과 권한은 postgres 초기화 스크립트에서 만든다.
- 의존성: `drizzle-orm`, 개발 의존성 `drizzle-kit`.

## Drizzle을 고른 이유

- 핵심 쿼리(조건부 전이, `FOR UPDATE SKIP LOCKED`, 알림 행 잠금과 `NOT EXISTS`, 토큰 버킷, `RETURNING`, 부분 인덱스)를 나타낼 수 있고, 어려운 부분도 같은 방식(`sql` 템플릿) 안에서 해결된다. 쿼리를 쓰는 방식이 하나로 유지된다.
- 스키마에서 타입이 추론된다.
- 읽고 나서 전체를 덮어쓰는 동작(unit of work)이 없어서, 동시성에서 lost update 함정이 없다.
- 빌더가 SQL에 가까워서, 심사 에이전트가 ADR과 대조하고 고의 결함 목록(ADR-0034)이 특정 문장을 가리키기에 충분하다.

## 검토한 후보

- **TypeORM**: NestJS에서 가장 익숙하지만, 핵심 쿼리는 raw SQL로 우회하게 되어 쓰는 방식이 둘로 갈린다. `save()`가 읽은 엔티티를 통째로 덮어써서, 워커가 그 사이 바꾼 상태를 지우는 lost update가 생길 수 있다.
- **Prisma + TypedSQL**: SQL 파일에서 타입 있는 함수를 만들 수 있지만, 코드 생성과 드라이버 어댑터 등 중간 단계가 많고, CRUD와 핵심 쿼리가 서로 다른 방식이 된다.
- **`pg` 드라이버로 SQL 직접 작성**: 가장 가볍고 SQL이 그대로 보이지만, 결과 타입을 직접 선언하고 마이그레이션 실행기를 직접 만들어야 한다.
- **Kysely**: Drizzle과 비슷한 절충안이지만, 스키마 정의에서 마이그레이션 SQL을 만드는 도구까지 한 벌로 갖춘 Drizzle을 택했다.
