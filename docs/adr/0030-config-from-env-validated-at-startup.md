# 설정은 환경변수로 받고, 기동 시 관계까지 검증해 틀리면 시작하지 않는다

- 모든 설정은 환경변수로 받는다. 기본값은 `docker-compose.yml`에 두어 `docker compose up`만으로 실행되게 하고, 운영에서는 같은 이미지에 환경변수만 바꿔 배포한다.
- `@nestjs/config`를 쓰고, 검증은 DTO 검증과 같은 class-validator로 한다. 작은 모듈을 직접 둘 수도 있지만, NestJS 공식 모듈이라 읽는 사람에게 익숙하고 붙이는 비용이 작다.
- 기동 시 모든 값을 검증하고, 하나라도 틀리면 어떤 키가 왜 틀렸는지 출력하고 종료한다. 잘못된 설정으로 돌다가 발송 중에 드러나는 것보다 시작하지 않는 편이 안전하다.
- 값 사이의 관계도 검증한다.
  - 생존 신호 < 발송 직전 확인 < 무효 선언(ADR-0004). 뒤집히면 워커가 스스로 멈추기 전에 무효로 선언되어 중복이 생길 수 있다.
  - 한 번에 꺼내는 수 ≤ 동시 발송 한도(ADR-0013).
- 기동 시 실제 적용된 설정값을 비밀값만 마스킹해(ADR-0028) 한 번 로그로 남긴다. 운영 중 "이 프로세스가 어떤 값으로 도는가"를 이 한 줄로 확인한다.

## 설정 항목 (기본값은 지금까지의 결정)

| 묶음 | 항목 |
| --- | --- |
| DB | 앱 계정 접속 주소, 마이그레이션 계정 접속 주소(ADR-0025) |
| 외부 API | 주소, HTTP 타임아웃 10초, 조회 타임아웃, 조회 대기 5초(ADR-0002) |
| 처리량 | 초당 50, 버킷 용량 10, 한 번에 꺼내는 수 10, 동시 발송 한도 50(ADR-0009, 0013) |
| 재시도 | 시작 간격 1초, 최대 간격 60초, 최대 8회(ADR-0014) |
| 서킷 브레이커 | 최근 20건, 실패 비율 절반, 정지 5~60초(ADR-0014) |
| 워커 생존 | 생존 신호 2초, 발송 직전 확인 5초, 무효 선언 15초, 쉴 때 확인 0.5초(ADR-0004, 0011) |
| 운영 | 포트, 로그 수준 |

## 검토한 후보

- **설정을 읽고 검증하는 모듈을 직접 작성**: 의존성이 하나 줄지만, `@nestjs/config`의 `.env` 로딩 외 기능이 필요 없더라도 표준 모듈이 읽는 사람의 비용을 더 줄인다.
