# ADR-0030. 환경변수 기반 설정 주입 및 기동 시 교차 제약 조건 검증

## 배경

개별 설정값이 유효하더라도 값 사이의 대소 관계가 어긋나면 동시성 안전장치가 무너진다. 예를 들어 외부 API 응답 한도가 발송 리스(lease) 기간보다 길면, 정상 요청이 응답을 대기하는 동안 다른 워커가 해당 건을 리스 만료로 인계(Takeover)받아 중복 발송이 발생한다. 이러한 설정 오류는 발송 도중에야 드러나므로 프로세스 기동 시점에 차단해야 한다.

## 결정

- **모든 설정은 환경변수로 주입받는다.** 기본값은 코드(`src/shared/config/app-config.ts`)와 `docker-compose.yml`에 두어 `docker compose up`만으로 실행되게 하고, 운영 환경에서는 동일 이미지에 환경변수만 변경하여 배포한다.
- **`@nestjs/config`를 사용하며, 검증은 요청 DTO 검증과 동일한 `class-validator`로 수행한다.**
- **기동 시점에 모든 설정값과 값 사이의 관계 제약을 검증한다.** 하나라도 위반하면 위반한 키와 사유를 출력하고 프로세스를 종료한다. 잘못된 설정으로 기동되어 발송 중에 장애가 발생하는 것보다 기동을 거부하는 편이 안전하다.
- **기동 시 실제로 적용된 설정값을 1회 로그로 기록한다.** 비밀값은 마스킹(masking) 처리한다(ADR-0028). 운영 중 프로세스가 어떤 설정값으로 실행 중인지 이 로그 1줄로 확인한다.

## 상세

### 설정 간 관계 검증 규칙

| 제약 조건                                                                                                   | 위반 시 문제점                                                                                                |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 외부 응답 한도 < 발송·조회 리스 기간, 사용자 조회 한도 < 작업 리스 기간(ADR-0004)                           | 정상 처리 중인 건이 응답 대기 중에 리스 만료로 인계(Takeover)된다                                             |
| 1회 점유(claim) 건수 ≤ 동시 발송 한도(ADR-0013)                                                             | 점유한 건을 즉시 발송할 동시 실행 슬롯이 부족해진다                                                           |
| 재시도 초기 간격 ≤ 최대 간격, 서킷 브레이커 최소 정지 시간 ≤ 최대 정지 시간(ADR-0014)                       | 대기 간격이 증가하지 않고 역전된다                                                                            |
| `api`의 쿼리 응답 한도 > 트랜잭션 유휴 한도(ADR-0039)                                                       | 멈춘 워커가 점유 중인 알림 행 잠금을 대기하던 발송 시작·취소 요청이, 잠금이 해제되기 전에 503 오류로 종료된다 |
| 역할별 필수 설정: `api`는 앱 DB 주소와 API 키, `worker`는 앱 DB 주소, `migrate`는 마이그레이션 DB 주소 필수 | 기동되더라도 해당 역할의 작업을 수행할 수 없다                                                                |

### 설정 항목 및 기본값

| 분류          | 설정 항목                                                                                                                                                 |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DB            | 앱 계정 접속 주소, 마이그레이션 계정 접속 주소(ADR-0025), `api`의 연결 획득 대기 한도 5초 및 쿼리 응답 한도 10초(ADR-0039)                                |
| 외부 API      | 주소, 발송 타임아웃 10초, 발송 내역 조회 타임아웃 10초, 사용자 조회 타임아웃 10초, 발송 내역 조회 대기 시간 5초(ADR-0002), 사용자 페이지 크기 1000        |
| 처리량        | 초당 토큰 보충량 50, 버킷 용량 10, 1회 점유(claim) 건수 10, 동시 발송 한도 50(ADR-0009, 0013)                                                             |
| 재시도        | 초기 간격 1초, 최대 간격 60초, 최대 8회, 지터(jitter) 폭 ±20%(ADR-0014)                                                                                   |
| 서킷 브레이커 | 최근 20건, 실패 비율 임계치 50%(절반), 정지 시간 5~60초, 연속 발동 판정 범위 60초(ADR-0014)                                                               |
| 리스 및 인계  | 발송 리스 30초, 작업 리스 30초, 조회 리스 30초, 리스 만료 회수·인계 주기 2초, 트랜잭션 유휴 한도 5초, 유휴 시 폴링 대기(sleep) 주기 0.5초(ADR-0004, 0011) |
| 운영          | 공개 포트, 관리 포트, 로그 레벨, API 키, 생존 판정 기준 30초(ADR-0026), 정상 종료 시 진행 중 응답 대기 상한 20초(ADR-0007)                                |

## 검토한 대안

- **설정 로드 및 검증 모듈 직접 작성**: 의존성이 하나 줄어드나, `@nestjs/config`는 NestJS 공식 모듈로 구조가 익숙하고 도입 비용이 낮다.
