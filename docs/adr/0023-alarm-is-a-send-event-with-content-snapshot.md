# ADR-0023. 알림은 발송 한 번의 단위이고 보낸 내용을 그대로 가진다. 템플릿과 제목 유일성은 두지 않는다

## 배경

같은 문구를 반복해서 보내는 운영은 흔하다. 이것을 "다시 쓸 내용(템플릿) → 발송 한 번 → 수신자별 발송 건"으로 나눠 보면, 지금의 알림(Alarm)은 가운데의 "발송 한 번"에 해당한다. 템플릿을 둘지, 제목이 겹쳐도 되는지 정해야 한다.

## 결정

- **알림은 보낸 내용을 복사해서 가진다.** 나중에 템플릿이 생겨도 알림은 템플릿을 가리키기만 하지 않고, 보낸 시점의 제목과 본문을 그대로 가진다. 템플릿은 수정되므로, 가리키기만 하면 "그때 실제로 무엇이 나갔는지"가 함께 바뀐다. 잘못 나간 알림을 정정하려면(ADR-0017) 실제로 나간 문구가 정확히 남아 있어야 한다.
- **템플릿은 만들지 않는다.** 범위 밖이고, 같은 내용을 다시 보내려면 같은 내용으로 알림을 하나 더 만들면 된다. 더한다면 생성할 때 템플릿 ID를 받아 내용을 복사하는 층을 위에 얹으면 되고, 지금 구조는 고칠 필요가 없다.
- **제목이 겹쳐도 된다.** 제목은 알림을 구별하는 관리용 이름이지만(ADR-0021), 같은 내용을 반복해 보내는 것이 흔하므로 제목이 겹치는 것이 정상이다. 겹치면 안 되는 것은 템플릿의 이름이다.

## 받아들이는 위험

서로 다른 운영자가 같은 캠페인을 각자 만들어 각자 시작하면 두 번 나간다. 발송 시작의 중복 방지(ADR-0016)는 같은 알림에만 동작하기 때문이다. 이 위험은 템플릿이나 승인 절차가 생기면 그 층에서 막는다.

## 검토한 후보

- **취소되지 않은 대량 알림끼리 제목 유일**: 위의 위험을 막고, 생성 재시도도 409와 기존 ID로 처리할 수 있다. 하지만 같은 문구를 반복해 보내는 정상적인 운영과 부딪힌다.
- **템플릿과 발송을 나눈 구조를 지금 도입**: 범위 밖이고, 나중에 얹어도 기존 구조가 바뀌지 않는다.
