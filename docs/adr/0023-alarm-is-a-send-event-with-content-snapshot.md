# Alarm은 발송 한 번의 단위이며 보낸 내용의 스냅숏을 가진다. 템플릿과 제목 유일성은 두지 않는다

같은 문구를 반복해서 보내는 운영은 흔하다. 이를 "재사용할 내용(템플릿) → 발송 이벤트 → 수신자별 발송 건"으로 나눠 보면, 지금의 Alarm은 발송 이벤트에 해당한다.

- **발송 이벤트는 내용을 복사해 갖는다.** 템플릿이 생겨도 이벤트는 템플릿을 참조만 하지 않고, 보낸 시점의 제목과 본문을 스냅숏으로 가진다. 템플릿은 나중에 수정되므로, 참조만 하면 "그때 실제로 무엇이 나갔는지"가 함께 바뀐다. 잘못 나간 알림을 정정할 때(ADR-0017) 실제로 나간 문구가 정확히 남아 있어야 한다.
- **템플릿은 만들지 않는다.** 명세 범위 밖이며, 같은 내용을 다시 보내려면 같은 내용으로 알림을 하나 더 만들면 된다. 추가한다면 알림 생성 시 템플릿 ID를 받아 내용을 복사하는 층을 위에 덧붙이면 되고, 지금 구조를 고칠 필요는 없다.
- **알림 제목의 유일성은 강제하지 않는다.** 제목은 알림을 구별하는 관리용 이름이지만(ADR-0021), 같은 내용을 반복 발송하는 것이 흔하므로 발송 이벤트의 제목은 반복되는 것이 정상이다. 유일해야 하는 것은 템플릿의 이름이다.

## 받아들이는 위험

서로 다른 운영자가 같은 캠페인을 각자 만들어 각자 시작하면 두 번 나간다. 발송 시작의 중복 방지(ADR-0016)는 같은 알림에 대해서만 동작하기 때문이다. 이 위험은 템플릿이나 승인 절차가 생기면 그 층에서 막는다.

## 검토한 후보

- **대량 알림끼리, 취소되지 않은 것 사이에서 제목 유일**: 위의 위험을 막고 생성 재시도도 409 + 기존 ID로 처리되지만, 같은 문구를 반복 발송하는 정상적인 운영과 부딪힌다.
- **템플릿 → 발송 이벤트의 3단계 구조를 지금 도입**: 명세 범위 밖이고, 나중에 덧붙여도 기존 구조가 바뀌지 않는다.
