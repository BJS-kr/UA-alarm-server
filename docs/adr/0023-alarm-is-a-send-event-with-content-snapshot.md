# ADR-0023. 발송 내용 스냅숏을 보유하는 단일 발송 이벤트로서의 알림 모델

## 배경

동일한 문구를 반복 발송하는 운영 환경을 고려할 때 도메인 개념은 "재사용할 문구(템플릿) → 1회 발송 이벤트 → 수신자별 발송 건(Delivery)"으로 구분된다. 현재 시스템의 알림(Alarm)은 이 중 "1회 발송 이벤트"에 해당한다. 이에 따라 템플릿 분리 여부와 알림 제목의 유일성 제약 여부를 결정해야 한다.

## 결정

- **알림은 발송 시점의 제목과 본문 스냅숏을 직접 보유한다**: 추후 템플릿 기능이 추가되더라도 알림은 템플릿 참조만 저장하지 않고 발송 시점의 제목과 본문을 값으로 복사해 저장한다. 템플릿 원본이 수정될 경우 참조만 유지하면 과거 알림의 실제 발송 문구 이력이 함께 변경되기 때문이다. 오발송 취소 후 정정 알림을 발송하려면(ADR-0017) 당시 실제로 전송된 문구가 그대로 보존되어야 한다.
- **별도 템플릿 리소스는 구현하지 않는다**: 현재 요구사항 범위 밖이며, 동일 문구의 재발송은 같은 내용으로 신규 알림을 생성하여 처리할 수 있다. 추후 템플릿을 도입할 경우 알림 생성 시 템플릿 ID를 받아 내용을 복사하는 상위 계층만 추가하면 되므로 현재 스키마를 변경할 필요가 없다.
- **알림 제목(`title`)의 중복을 허용한다**: 제목은 관리용 식별 이름이지만(ADR-0021) 동일 문구의 반복 발송이 정상적인 운영 패턴이므로 제목 중복을 허용한다. 유일성 제약이 필요한 대상은 발송 이벤트가 아니라 템플릿 이름이다.

## 결과 및 한계

서로 다른 운영자가 동일한 캠페인 알림을 각각 생성하여 발송을 시작하면 중복 발송된다. 발송 시작의 멱등성 보장(ADR-0016)은 단일 알림 ID 내부에서만 동작하기 때문이다. 이러한 운영상 중복 발송은 추후 캠페인 템플릿이나 발송 승인 절차가 도입될 때 해당 계층에서 통제한다.

## 검토한 대안

- **미취소 대량 알림 간 제목 유일성 제약 적용**: 운영자의 중복 생성 및 생성 요청 재시도를 `409`와 기존 ID 반환으로 차단할 수 있으나, 동일 제목의 정기·반복 발송이라는 정상 운영 흐름을 막게 된다.
- **템플릿과 발송 이벤트를 분리한 스키마 즉시 도입**: 현재 요구사항 범위를 벗어나며 추후 상위 계층으로 추가하더라도 기존 테이블 구조 변경이 불필요하다.
