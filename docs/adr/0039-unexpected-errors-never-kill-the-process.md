# 예상하지 못한 오류로 프로세스가 죽지 않게 하고, 요청에는 반드시 응답한다

서버가 아무 기록 없이 툭 종료되는 일은 없어야 한다. 예상하지 못한 오류는 받아서 로그와 메트릭으로 남기고 계속 돈다. 일부러 끝내는 경우는 시작하지 못했을 때 하나뿐이다.

## 받는 곳은 위쪽 몇 군데로 모은다

try/catch를 곳곳에 바르지 않는다. 오류가 올라오는 꼭대기마다 한 번씩, 같은 방식으로 받는다.

| 꼭대기 | 받는 방식 |
| --- | --- |
| 프로세스 | api와 worker가 시작할 때 `unhandledRejection`, `uncaughtException`을 받는 안전망을 등록한다. 로그(error)를 남기고 `alarm_unhandled_errors_total`을 올린 뒤 계속 돈다 |
| HTTP 요청 | 전역 예외 필터가 모든 오류를 Problem Details로 바꾼다(ADR-0019). 예상하지 못한 오류는 500, DB를 쓸 수 없으면 503이다 |
| worker의 작업 루프 | 다섯 루프(발송, 결과 확인, 펼치기, 취소 정리, 넘겨받기)가 같은 `PollingLoop`를 쓴다. 한 바퀴가 오류로 끝나면 로그와 `alarm_loop_errors_total`을 남기고 잠깐 쉰 뒤 다음 바퀴를 돈다 |
| 루프 밖에서 도는 발송 한 건 | 발송 작업을 등록하는 한 곳에서 받는다. 한 건의 오류가 루프와 다른 건에 번지지 않는다 |
| 관리 포트 | 응답을 끝까지 만든 뒤 한 번에 보낸다. 만드는 도중 실패하면 503으로 답하고 로그를 남긴다 |

## 요청은 반드시 끝난다

api의 DB 풀에 연결 대기 한도(`DB_ACQUIRE_TIMEOUT_MS`, 기본 5초)와 쿼리 응답 한도(`DB_QUERY_TIMEOUT_MS`, 기본 30초)를 둔다. 한도가 없으면 풀이 바닥났을 때 요청이 응답 없이 끝없이 기다린다. 한도를 넘으면 503으로 답한다. Drizzle은 드라이버 오류를 감싸 `cause`에 두므로, 503 판단은 `cause`를 따라가며 한다.

worker의 풀에는 클라이언트 쪽 한도를 두지 않는다. 멈춘 워커가 쥔 알림 행 잠금이 풀리기를 기다리는 것이 정상이라, 한도에 걸리면 멀쩡한 워커의 결과 기록이 실패한다. 그 잠금은 서버 쪽 한도(트랜잭션 유휴 한도 5초)가 풀어 준다(ADR-0004).

## 일부러 끝내는 경우

시작하지 못했을 때(설정 오류 등)만 fatal 로그에 사유를 남기고 종료 코드 1로 끝난다. 일을 시작할 수 없고, 기동 단계라 처리 중인 일이 없다.

결과를 DB에 기록하지 못해도 끝내지 않는다. DB 쓰기는 간격을 늘려 가며 몇 번 재시도하고, 끝내 실패하면 그 오류를 루프 꼭대기가 받아 로그와 `alarm_loop_errors_total`로 남긴다. 기록하지 못한 건은 기한이 지나 다른 워커가 넘겨받고(ADR-0004), 펼치기는 같은 커서부터 다시 받고, 취소 정리는 기한 뒤 다시 집힌다.

처음에는 이 경우에도 끝냈다. 점유를 DB 세션으로 판정하던 때라, 끝내야 잠금이 풀려 다른 워커가 넘겨받았기 때문이다. 기한 방식으로 바꾼 뒤에는 끝낼 이유가 없어졌고, 끝내면 DB가 몇 초만 응답하지 않아도 모든 워커가 한꺼번에 재시작했다.

migrate는 한 번 돌고 끝나는 작업이라 실패하면 종료 코드 1로 끝나는 것이 계약이다.

## 처리되지 않은 예외 뒤에도 계속 도는 위험

Node는 `uncaughtException` 뒤의 상태를 보장하지 않는다. 그래도 계속 도는 쪽을 택했다. 이 시스템의 정확성은 메모리가 아니라 DB에 있고(조건부 쓰기, 펜싱), 망가진 프로세스는 생존 확인이 잡는다. worker는 작업 루프가 30초 동안 돌지 않으면 생존 확인이 실패해 재시작된다(ADR-0026). 아무 기록 없이 죽는 것보다, 기록을 남기고 생존 확인에 맡기는 편이 원인을 찾기 쉽다.

## 검토한 후보

- **예외 뒤 바로 종료(Node 권장)**: 상태를 믿을 수 없을 때는 안전하지만, 요청 하나의 버그가 프로세스 전체를 내리고, 원인 로그가 남기 전에 죽을 수 있다.
- **모듈마다 try/catch**: 받는 방식이 곳곳에서 달라지고, 하나만 빠뜨려도 프로세스가 죽는다.
