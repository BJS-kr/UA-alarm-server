# ADR-0010. 워커는 기본 2대로 구성하며 컨테이너당 단일 프로세스로 실행한다

## 배경

전체 발송 처리량은 외부 API 상한(초당 50건)에 제한되어 있다. 비동기 I/O 기반의 Node.js 단일 프로세스만으로도 초당 50건 처리는 충분히 감당할 수 있으므로 처리량 측면에서는 워커 1대로도 충분하다.

## 결정

Docker Compose의 기본 `worker` 레플리카 수(`replicas`)를 2로 설정한다. 단일 컨테이너 내부에 여러 프로세스를 띄우는 방식(Node.js `cluster` 모드)은 사용하지 않는다.

## 근거

- **고가용성 확보**: 워커가 1대뿐이면 해당 워커 비정상 종료 시 컨테이너가 재시작될 때까지 전체 발송이 중단된다. 2대로 구성하면 1대가 중단되더라도 남은 워커가 대기(`PENDING`) 건을 중단 없이 계속 발송하며, 중단된 워커가 점유 중이던 건은 리스(30초) 만료 후 인계(Takeover)받아 처리한다(ADR-0004).
- **다중 워커 동시성 경로의 상시 검증**: 리스 만료 인계와 동시 점유(claim) 경로가 개발 및 테스트 환경에서도 상시 실행되므로 다중 워커 환경에서만 발생하는 경합 버그를 조기에 발견할 수 있다.
- **3대 이상 증설 시 실익 없음**: 전역 처리량 상한(초당 50건)이 고정되어 있어 워커를 3대 이상으로 늘려도 처리량은 증가하지 않고 DB 연결 수와 토큰 버킷 행 경합만 증가한다. 단, `--scale worker=N` 명령을 통한 수평 확장은 그대로 지원하고 검증한다.
- **1 컨테이너 = 1 프로세스 = 1 워커 원칙**: 워커 ID 부여와 종료 시그널(`SIGTERM`) 처리 구조를 단순하게 유지한다.
