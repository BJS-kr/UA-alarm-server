# ADR-0010. 워커는 기본 2대이고, 컨테이너 하나에 프로세스 하나다

## 배경

처리량은 외부 상한(초당 50건)에 묶여 있다. Node 프로세스 하나는 비동기 I/O로 이 정도를 충분히 감당한다. 처리량만 보면 워커 1대로도 된다.

## 결정

compose의 기본 worker 수(replicas)를 2로 둔다. 한 컨테이너 안에 프로세스를 여러 개 띄우지 않는다(Node cluster 모드를 쓰지 않는다).

## 이유

- **가용성**: 1대면 그 워커가 죽었을 때 재시작될 때까지 발송이 멈춘다. 2대면 남은 워커가 대기 건을 계속 보내고, 죽은 워커가 쥐고 있던 건은 기한(30초)이 지나면 넘겨받는다(ADR-0004).
- **여러 워커에서만 도는 경로가 늘 돈다**: 넘겨받기와 동시 꺼내기가 개발 중에도 늘 실행된다. 여러 워커에서만 드러나는 버그가 숨지 않는다.
- **3대 이상은 얻는 것이 없다**: 처리량은 그대로이고, DB 연결과 토큰 버킷 행을 두고 다투는 일만 는다. `--scale worker=N`은 그대로 지원하고 테스트한다.
- **컨테이너 = 프로세스 = 워커 하나**: 워커 ID와 종료 처리를 단순하게 유지한다.
