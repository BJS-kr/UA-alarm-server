# Delivery 상태는 여섯 개이며, 최종 상태는 SENT·FAILED·CANCELED다

| 상태 | 뜻 |
| --- | --- |
| PENDING | 꺼낼 수 있거나, 재시도 시각을 기다리는 상태 |
| IN_FLIGHT | 워커가 쥐고(owner) 외부로 보내는 중 |
| UNCONFIRMED | 보냈는지 모르는 상태. 조회 시각이 되면 조회한다 |
| SENT | 202를 받았거나 조회로 기록을 확인함 |
| FAILED | 400을 받았거나 재시도를 모두 씀 |
| CANCELED | 알림 취소로 보내지 않음 |

```
PENDING ──꺼냄──▶ IN_FLIGHT ──202────────────────────────▶ SENT
   ▲                   │──400 / 시도 소진────────────────▶ FAILED
   │                   │──500·503·연결 거부, 429 ───────┐
   ├────────────────────────────────────────────────────┘ (재시도 시각을 두고 되돌림)
   │                   │──정상 종료 시 반납 (보내지 않은 건)
   │                   │──타임아웃, 보낸 뒤 끊김, 주인 소멸 ──▶ UNCONFIRMED
   │                                                         │──조회: 기록 있음 ──▶ SENT
   └──────────── 조회: 기록 없음, 시도 남음 ─────────────────┤
                                                             │──조회: 기록 없음, 시도 소진 ──▶ FAILED
                                                             │──조회: 기록 없음, 알림 취소 중 ──▶ CANCELED
PENDING ──알림 취소 정리──▶ CANCELED
```

- **최종 상태는 SENT, FAILED, CANCELED다.** 한 번 들어가면 나오지 않는다. 완료 판정의 "끝나지 않은 건"은 PENDING, IN_FLIGHT, UNCONFIRMED다(ADR-0018).
- **조회에서 기록이 없으면 바로 보내지 않고 PENDING으로 되돌린다.** 재발송도 토큰을 받아야 하고(ADR-0009) 우선순위 순서를 지켜야 하므로(ADR-0011) 같은 꺼내기 경로를 탄다.
- **조회도 꺼내기와 같은 방식으로 쥐고 한다.** 조회는 읽기만 하므로 겹쳐도 해롭지 않으며, 결과 반영은 `WHERE status = 'UNCONFIRMED'` 조건으로 한 번만 일어난다.
- **정상 종료 시 반납하는 건(ADR-0007)은 IN_FLIGHT에서 PENDING으로 돌아간다.** 확실히 보내지 않은 건이라 즉시 안전하다.
- 모든 전이는 ADR-0016과 같은 조건부 UPDATE이며, IN_FLIGHT에서 나가는 전이는 owner와 시도 번호 조건을 함께 건다(ADR-0004).
- 보내는 중인 상태를 SENDING이 아니라 IN_FLIGHT로 부르는 이유: Alarm 상태에 SENDING(발송이 진행 중인 알림)이 있어, 같은 이름이 두 테이블과 로그에서 다른 뜻으로 섞인다. CANCELED는 두 곳에서 같은 뜻이라 그대로 쓴다.
