# ADR-0032. Delivery 6단계 상태 모델 및 상태 전이 규칙

## 배경

Delivery는 단일 수신자에게 알림을 발송하는 개별 작업 단위다. 이 작업은 대기, 전송 중, 실패 후 재시도 대기, 전송 여부 미확정으로 인한 발송 내역 조회 대기 등 여러 단계를 거친다. 상태를 어떻게 정의하느냐가 미종료 건의 잔존 여부와 실제 발송 성공 여부를 정확히 판별하는 기준이 된다.

## 결정

Delivery 상태는 6개로 정의하며, 종료 상태는 `SENT`, `FAILED`, `CANCELED`다.

| 상태          | 의미                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------- |
| `PENDING`     | 점유(claim) 가능 상태이거나 재시도 예정 시각을 대기 중이다                                   |
| `IN_FLIGHT`   | 워커가 점유(담당 워커 ID 및 리스 만료 시각 `lease_until` 설정)하여 외부로 전송 중이다        |
| `UNCONFIRMED` | 전송 여부 미확정 상태다. 조회 예정 시각이 도래하면 발송 내역 조회(Reconciliation)를 수행한다 |
| `SENT`        | `202` 응답을 받았거나 발송 내역 조회로 발송 기록을 확인했다                                  |
| `FAILED`      | 영구 오류(`400`)를 받았거나 최대 시도 횟수를 모두 소진했다                                   |
| `CANCELED`    | 상위 알림이 취소되어 발송하지 않았다                                                         |

## 상세

### 상태 전이 규칙

| 현재 상태     | 이벤트 및 조건                                                                                                                                    | 다음 상태                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `PENDING`     | 워커가 점유(claim)                                                                                                                                | `IN_FLIGHT`                                 |
| `PENDING`     | 알림 취소 정리(ADR-0017)                                                                                                                          | `CANCELED`                                  |
| `IN_FLIGHT`   | `202` 응답 수신                                                                                                                                   | `SENT`                                      |
| `IN_FLIGHT`   | `400` 응답 수신, 또는 시도 횟수 소진                                                                                                              | `FAILED`                                    |
| `IN_FLIGHT`   | `500`·`503`·연결 거부(재시도 시각 설정), `429`, 서킷 브레이커 개방 중의 `5xx`·연결 오류(ADR-0014), 미전송 건 반납(정상 종료, 발송 직전 취소 확인) | `PENDING`                                   |
| `IN_FLIGHT`   | 타임아웃, 요청 전송 후 연결 끊김, `502`·`504`, 리스 만료로 인한 인계(Takeover, ADR-0004)                                                          | `UNCONFIRMED`                               |
| `UNCONFIRMED` | 발송 내역 조회: 기록 있음                                                                                                                         | `SENT`                                      |
| `UNCONFIRMED` | 발송 내역 조회: 기록 없음, 잔여 시도 남음                                                                                                         | `PENDING`                                   |
| `UNCONFIRMED` | 발송 내역 조회: 기록 없음, 시도 횟수 소진                                                                                                         | `FAILED`                                    |
| `UNCONFIRMED` | 발송 내역 조회: 기록 없음, 상위 알림이 취소 진행 중                                                                                               | `CANCELED`                                  |
| `UNCONFIRMED` | 발송 내역 조회 실패                                                                                                                               | `UNCONFIRMED` 유지(간격을 늘려 재조회 예약) |

`PENDING`으로 가는 모든 전이는 상위 알림이 `SENDING` 상태가 아니면 `PENDING` 대신 `CANCELED`로 전이한다(ADR-0017).

### 운영 및 동시성 규칙

- **종료 상태는 `SENT`, `FAILED`, `CANCELED`다.** 한 번 진입하면 다른 상태로 변경되지 않는다. 완료 판정이 확인하는 미종료 상태는 `PENDING`, `IN_FLIGHT`, `UNCONFIRMED`다(ADR-0018).
- **발송 내역 조회에서 기록이 없으면 즉시 재발송하지 않고 `PENDING`으로 되돌린다.** 재발송 시에도 토큰을 할당받아야 하고(ADR-0009) 우선순위 순서를 준수해야 하므로(ADR-0011), 동일한 점유(claim) 경로를 거친다.
- **발송 내역 조회도 점유(claim)와 동일하게 리스(30초 만료 시각)를 설정하여 수행한다.** 조회 자체는 읽기 전용이므로 중복 실행되어도 무해하며, 상태 확정 반영은 `WHERE status = 'UNCONFIRMED'` 조건으로 한 번만 수행된다.
- **모든 상태 전이는 조건부 `UPDATE`로 처리한다**(ADR-0016). `IN_FLIGHT`에서 나가는 전이는 담당 워커 ID와 시도 번호 조건을 함께 검증한다(ADR-0004).

### 명칭 구분: `SENDING` 대신 `IN_FLIGHT`

알림(Alarm) 상태에 이미 `SENDING`(발송 진행 중인 알림)이 존재한다. Delivery의 전송 중 상태까지 `SENDING`으로 명명하면 두 테이블과 로그에서 동일한 이름이 서로 다른 의미로 혼용된다. 반면 `CANCELED`는 두 테이블에서 의미가 같으므로 동일하게 사용한다.
