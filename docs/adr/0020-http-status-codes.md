# ADR-0020. HTTP 상태 코드 사용 규칙

## 배경

상태 코드만 보고도 클라이언트가 무엇이 잘못됐는지, 다시 보내도 되는지 알 수 있어야 한다. 특히 발송 시작과 취소는 응답할 때 일이 끝나지 않았을 수 있다.

## 결정

| 상황 | 코드 |
| --- | --- |
| 알림 생성 성공 | 201 Created + `Location` |
| 조회 성공 | 200 |
| 발송 시작이나 취소 뒤 아직 진행 중(SENDING, CANCELING) | 202 Accepted |
| 발송 시작이나 취소 뒤 이미 끝난 상태(COMPLETED, CANCELED) | 200 |
| 요청 형식이나 값의 오류(JSON 파싱 실패, 필드 누락, 길이 초과, 긴급 수신자 규칙 위반, ID 형식 오류) | 400 |
| 인증 실패(ADR-0033) | 401 |
| 알림 없음, 없는 경로 | 404 |
| 경로는 있는데 메서드가 틀림(예: `DELETE /v1/alarms`) | 405 + `Allow` |
| 지금 상태로는 할 수 없는 요청(취소된 알림의 시작, 완료된 알림의 취소) | 409 |
| 요청 본문이 너무 큼 | 413 |
| 본문이 JSON이 아님 | 415 |
| 예상하지 못한 서버 오류 | 500 |
| DB 연결 불가 등 잠시 처리할 수 없음 | 503 |

## 이유

- **202와 200은 "응답할 때 일이 아직 진행 중인가"로만 가른다.** 발송 시작(SENDING)은 202, 생성 상태에서의 취소(CANCELED)는 200, 발송 중 취소(CANCELING)는 202, 완료된 알림의 재시작 요청은 200이다.
- **검증 실패는 모두 400이다.** 어떤 필드가 왜 틀렸는지는 Problem Details의 `errors`에 담는다(ADR-0019).
- **메서드가 틀리면 405다.** 404는 "그런 주소가 없다"는 뜻이라, 주소를 잘못 쓴 것처럼 보인다. 405와 `Allow` 헤더는 "주소는 맞고, 쓸 수 있는 메서드는 이것"이라고 알려 준다. 허용 메서드는 OpenAPI 문서에서 읽으므로, 경로를 더해도 따로 고칠 곳이 없다.
- **본문이 JSON이 아니면 415다.** 서버는 JSON 본문만 읽는다. 다른 형식이면 본문을 읽지 못해, 필드를 다 넣었는데도 "필드가 없다"는 400이 나간다.

## 검토한 후보

- **형식 오류는 400, 규칙 위반은 422로 구분**: "제목 길이 초과"처럼 둘의 경계가 애매하다. 필드별 사유는 `errors`에 담기므로, 코드를 나눠 얻는 정보가 없다.

## 바뀐 경위

처음에는 405와 415가 없었다. 메서드가 틀린 요청은 404를, JSON이 아닌 본문은 "모든 필드 없음" 400을 받았다. 심사(4회차)의 지적으로 더했다.
