# HTTP 상태 코드 사용 규칙

| 상황 | 코드 |
| --- | --- |
| 알림 생성 성공 | 201 Created + `Location` |
| 조회 성공 | 200 |
| 발송 시작·취소 후 아직 진행 중(SENDING, CANCELING) | 202 Accepted |
| 발송 시작·취소 후 이미 끝난 상태(COMPLETED, CANCELED) | 200 |
| 요청 형식·값 오류(JSON 파싱 실패, 필드 누락, 길이 초과, 긴급 수신자 규칙 위반, ID 형식 오류) | 400 |
| 알림 없음 | 404 |
| 현재 상태로 불가능한 요청(취소된 알림 시작, 완료된 알림 취소) | 409 |
| 예상하지 못한 서버 오류 | 500 |
| DB 연결 불가 등 일시적으로 처리 불가 | 503 |

- 202와 200은 "응답 시점에 일이 아직 진행 중인가"로만 가른다. 발송 시작(→ SENDING)은 202, 생성 상태에서의 취소(→ CANCELED)는 200, 발송 중 취소(→ CANCELING)는 202, 완료된 알림에 대한 재시작 요청은 200이다.
- 검증 실패는 모두 400이다. 어떤 필드가 왜 틀렸는지는 Problem Details의 `errors`에 담는다(ADR-0019).

## 검토한 후보

- **형식 오류는 400, 규칙 위반은 422로 구분**: "제목 길이 초과"처럼 둘의 경계가 애매하고, 필드별 사유는 `errors`에 담기므로 코드를 나눠 얻는 정보가 없다.
