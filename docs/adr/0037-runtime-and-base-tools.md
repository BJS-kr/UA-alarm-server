# ADR-0037. 런타임과 기본 도구

## 결정

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| Node | 24 LTS | LTS이고 개발 환경과 같다. Node 26은 2026년 10월 말에 LTS가 된다 |
| NestJS | 12 | 최신 메이저(2026-08). TypeScript는 Nest CLI가 쓰는 6.0을 따른다. TS 7에는 Nest가 아직 맞추지 않았다 |
| PostgreSQL | 18 | `uuidv7()`이 내장되어 확장이 필요 없다 |
| 알림 ID | UUIDv7 (DB 기본값) | uuid 요구를 지키면서 ID 순서가 생성 순서다. 목록 커서(ADR-0024)를 ID 하나로 하고, 인덱스에도 순서대로 쌓인다 |
| Delivery ID | bigint 자동 증가 | 내부용이며, 꺼내는 순서와 커서의 기준이다. 밖에서는 알림 ID와 수신자 ID로 식별한다 |
| HTTP 클라이언트 | `node:http` + `http.Agent` | keepAlive와 소켓 수(ADR-0013)를 표준 라이브러리로 설정한다. 내장 `fetch`는 연결 수를 정하려면 `undici` 패키지가 필요하다 |
| 입력 검증 | class-validator + class-transformer | NestJS 표준 조합이다. `forbidNonWhitelisted`로 모르는 필드를 거절한다(ADR-0021) |
| OpenAPI | @nestjs/swagger | 컨트롤러와 DTO에서 만들어 `/docs`로 제공하고, `docs/openapi.json`을 저장소에도 커밋한다. 문서의 `openapi` 필드는 3.0.x다 |
| 패키지 매니저 | npm | Node에 기본으로 들어 있어 도구가 늘지 않는다 |

## "보냈는지 모르는" 오류의 기준

기준은 하나다. **요청 바이트를 커널에 모두 넘겼는가**(요청 스트림의 `finish`).

- **넘기기 전의 실패**(연결 거부, 호스트 없음, 연결 단계 시간 초과 등): 서버는 완전한 요청을 받지 못했으므로 처리할 수 없다. 나가지 않은 것으로 보고 재시도한다(ADR-0014).
- **넘긴 뒤의 실패**(타임아웃, 응답 도중 끊김): 결과 미확정으로 둔다(ADR-0032).
- keepAlive 연결이 서버 쪽에서 이미 닫혀 있어 쓴 직후 끊기는 경우도, 바이트는 넘긴 뒤이므로 결과 미확정이다. 실제로는 안 나갔을 가능성이 높지만 확실하지 않고, 손해는 조회 한 번이다.

처음에는 연결 단계 오류 코드 목록(ECONNREFUSED 등)도 함께 봤다. 변이 테스팅에서 그 조건이 결과를 바꾸지 않는 것이 드러나 기준을 하나로 줄였다(ADR-0034).
