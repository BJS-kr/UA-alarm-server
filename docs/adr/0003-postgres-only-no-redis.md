# ADR-0003. PostgreSQL 하나로 발송 상태, 작업 대기열, 처리량 제한을 처리한다 (Redis, BullMQ 없음)

## 결정

수신자별 발송 상태(Delivery)는 조회해야 하므로 어차피 영속 DB에 있어야 한다. 그 행을 그대로 작업 대기열로 쓴다. 별도 큐나 Redis는 두지 않는다.

- 워커는 `FOR UPDATE SKIP LOCKED`로 Delivery를 꺼낸다. 여러 워커가 동시에 꺼내도 같은 행을 두 번 집지 않는다.
- 한 번에 꺼내는 수는 받은 토큰 수만큼이다. 평소에는 1건 남짓, 많아야 10건이다(ADR-0009).
- 긴급 알림은 꺼내는 쿼리의 정렬 순서로 앞에 선다(ADR-0011).

BullMQ와 Redis가 주는 기능을 하나씩 확인하고, 각각을 PostgreSQL로 대신할 수 있어서 뺐다(ADR-0005).

## BullMQ가 주는 기능과 대신하는 수단

| 기능 | BullMQ | 이 프로젝트 |
| --- | --- | --- |
| 우선순위 | `priority` 옵션 | 꺼내는 쿼리의 `ORDER BY priority` |
| 재시도와 백오프 | `attempts`, `backoff` | Delivery의 다음 시도 시각 컬럼 |
| 여러 워커에 나누기 | 내장 | `FOR UPDATE SKIP LOCKED` |
| 워커가 죽었을 때 복구 | 시간 기반 잠금. 멈춘 작업(stalled job)을 그대로 다시 실행 | 건마다 적은 기한. 넘겨받은 건은 조회한 뒤에만 다시 보내고, 늦은 쓰기는 펜싱으로 막는다(ADR-0004) |
| 전체 처리량 제한 | 큐 단위 limiter | PG 행 하나의 토큰 버킷(ADR-0009) |

## 이유

1. **원본이 하나다.** 큐와 DB를 함께 쓰면 발송 시작(행 삽입과 작업 적재), 완료(DB 기록과 큐 완료 처리), 취소(DB와 큐에 남은 작업)마다 둘이 어긋날 수 있고, 그것을 맞추는 코드가 따로 필요하다. 결국 워커가 작업마다 DB를 확인하게 되어 큐는 중복 정보가 된다.
2. **부하가 작다.** 외부 상한 초당 50건이 전체 처리량의 상한이다. 초당 49건을 보낼 때 DB 커밋은 워커 2대에서 초당 185회, 3대에서 221회였고 처리량에 영향이 없었다.
3. **판단 기준이 하나다.** 기한, 순서, 처리량 제한을 모두 DB의 행과 DB 시계로 판단한다. 두 시스템의 판단이 엇갈릴 일이 없다.
4. **운영 대상이 하나 줄어든다.** Redis의 영속성 설정, 백업, 장애 조치, 모니터링이 필요 없다.
5. **처리량 카운터도 PG로 충분하다.** 토큰 버킷 행의 갱신은 초당 72~94회(워커 2~3대)이고, 인덱스를 건드리지 않는 HOT 갱신이라 처리량에 영향이 없다.

DB를 작업 대기열로 쓰는 방식은 Rails 8의 기본 큐(Solid Queue), pg-boss(Node), Oban(Elixir)과 같은 계열이다.

## 검토한 후보

- **BullMQ(Redis) 큐 + PG 상태**: 우선순위, 재시도, 복구가 내장돼 있다. 그러나 1번의 이중 기록 문제가 생긴다. 복구도 시간 기반 잠금이라, 이벤트 루프가 막히면 같은 작업이 두 번 실행될 수 있다(공식 문서의 stalled job 경고). 우리도 시간 기한을 쓰지만, 다시 보내기 전에 조회하고 늦은 쓰기를 펜싱으로 막는다. BullMQ를 써도 이 두 장치는 직접 만들어야 한다.
- **워커 메모리 큐 + 장애 시 다시 채우기**: 워커가 죽으면 큐가 사라진다. 다시 채우려면 어디까지 보냈는지 DB를 봐야 하므로 결국 DB가 원본이다.
- **PG 큐 확장(pgmq)**: 메시지가 확장의 자체 테이블에 있어서, 수신자별 상태와 남은 일이 다시 두 곳에 나뉜다. 공식 postgres 이미지에도 들어 있지 않다.
- **PG 큐 + 처리량 제한만 Redis**: 처리량 카운터도 PG로 충분해, 구성 요소를 하나 더 둘 이유가 없다.

## 다시 볼 조건

외부 처리량이 초당 수천 건 단위로 커지거나 DB가 병목이 되면, 처리량 제한부터 Redis로 옮긴다.

## 바뀐 경위

처음에는 10건 안팎씩 묶어 꺼내므로 DB 왕복이 초당 수십 번이라고 봤다. 실제로는 토큰이 1개 남짓씩 나가서 꺼내기도 거의 1건씩이었다(ADR-0009). 위의 커밋 수는 그 상태에서 잰 값이다.
