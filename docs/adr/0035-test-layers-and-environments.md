# 테스트는 단위·통합·끝단 세 층이며, DB는 항상 실제 PostgreSQL을 쓴다

| 층 | 검증 대상 | DB | 외부 API | 비고 |
| --- | --- | --- | --- | --- |
| 단위 | TS 순수 로직(재시도 간격, 응답 분류, 서킷 브레이커, 상태 전이표, 마스킹, 입력 검증, 설정 관계 검증) | 없음 | 없음 | 변이 테스팅 대상(ADR-0034) |
| 통합 | SQL과 동시성(꺼내기, 넘겨받기, 무효 선언, 취소, 완료 판정, 토큰 버킷, 우선순위·순서, 펼치기 재개) | 실제 PG | 테스트용 가짜 서버 | 고의 결함 목록(ADR-0034)을 이 층에서 돌린다 |
| 끝단 | 전체 시스템이 명세대로 동작하는가 | 실제 PG | 실제 mock 이미지 | 느리고 무작위성이 있어 별도 스크립트로 실행 |

## 세부

- **DB는 실제 PostgreSQL이다.** 정확성의 핵심이 SQL이고, 메모리용 가짜 DB(pg-mem 등)는 `SKIP LOCKED`와 advisory lock을 지원하지 않는다. 운영과 같은 postgres 이미지를 쓴다.
- **통합 테스트의 외부 API는 테스트 안에 띄우는 가짜 HTTP 서버다.** 실제 mock은 오류가 무작위라 특정 상황을 골라 만들 수 없다. 가짜 서버는 mock과 같은 계약(사용자 조회, 발송, 발송 내역 조회)을 따르며 "이 수신자는 20초 뒤 202", "다음 3건은 503" 같은 동작을 미리 정할 수 있고, 받은 요청을 모두 기록해 "수신자마다 정확히 한 번"을 직접 확인한다.
- **워커 다중화와 장애**: 여러 워커는 한 테스트 프로세스 안에서 DB 연결과 워커 ID를 따로 가진 인스턴스로 띄운다. 크래시는 커널이 소켓을 닫아야 하므로 워커를 자식 프로세스로 띄워 SIGKILL을 보낸다. 멈춤은 생존 신호를 멈춰 무효 선언과 넘겨받기를 확인한다.
- **끝단 테스트**: 실제 mock 이미지를 사용자 2000명으로 띄우고, 대량·긴급 알림을 함께 보내면서 발송 도중 워커 하나를 `docker kill`한다. 끝나면 mock의 발송 내역 조회로 수신자마다 정확히 한 번 기록됐는지(중복 0, 누락 0), 메트릭으로 429가 지속되지 않았는지 확인한다.
- **실행은 Docker로 한다.** `docker compose --profile test run --rm test` 하나로 단위·통합 테스트를 돌리며, 평가자 PC에 Node가 없어도 된다. 테스트 PG는 compose의 postgres 서비스를 쓰므로 Testcontainers 같은 의존성이 필요 없다.
- 테스트 러너는 NestJS 기본인 Jest다.

## 검토한 후보

- **메모리용 가짜 DB**: 핵심 SQL 기능을 지원하지 않는다.
- **통합 테스트에도 실제 mock 사용**: 무작위성 때문에 특정 장애 상황을 재현할 수 없다.
- **Testcontainers**: 코드에서 컨테이너를 띄워 편하지만, compose로 같은 일을 할 수 있어 의존성을 늘리지 않는다.
