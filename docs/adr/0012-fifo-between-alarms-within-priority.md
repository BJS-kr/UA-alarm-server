# ADR-0012. 동일 우선순위 내에서는 먼저 시작한 알림부터 순차 처리한다

## 배경

대량 알림 두 개를 연달아 시작할 때 두 알림을 번갈아 발송할 수도 있고 먼저 시작한 알림부터 차례로 발송할 수도 있다. 이 선택은 각 알림의 완료 시점과 장애 발생 시 미완료 상태로 남는 알림의 범위를 결정한다.

## 결정

동일한 우선순위의 알림이 여러 개 진행 중이면, 점유 가능한 건 가운데 먼저 시작한 알림의 건부터 점유(claim)한다. 점유 정렬 순서는 `priority, 알림 시작 순번, Delivery 순번`이다. 알림 시작 순번은 발송 시작 시점에 채번하여 `Delivery`에 복사해 둔다.

## 근거

- **완료 시점 예측 및 평균 소요 시간 단축**: 선행 알림이 끝나면 후속 알림이 시작된다고 예측할 수 있다. 동일 크기의 대량 알림 두 개라면 각각 33분, 66분에 완료된다. 번갈아 발송하면 두 알림 모두 66분에 완료되므로 평균 완료 시간도 순차 발송이 짧다.
- **장애 영향 범위 격리**: 발송 중 장애가 발생하면 두 알림이 함께 중간에 중단되는 대신 하나는 완료되고 하나는 시작 전 상태로 남을 가능성이 높다.
- **취소 여유 시간 확보**: 뒤에서 대기하는 알림은 선행 알림이 끝날 때까지 한 건도 발송되지 않으므로 도중에 취소해도 이미 발송된 건이 남지 않는다.
- 신속한 발송이 필요한 알림은 긴급 알림으로 분류하여 우선 발송한다.

## 상세

- **순서는 현재 점유 가능한 건 사이에서만 적용된다**(ADR-0011과 동일한 원리). 선행 알림에 재시도나 발송 내역 조회 시각을 기다리는 건만 남으면 후속 알림의 건을 점유한다. 선행 알림의 건이 다시 점유 가능해지면 해당 건이 우선 점유된다. 이를 통해 토큰이 유휴 상태로 낭비되지 않는 대신, 선행 알림의 후반부와 후속 알림의 초반부가 일시적으로 겹친다.
- **재시도 건은 해당 알림 내의 기존 순번 위치를 유지한다.** 보장해야 하는 조건은 재시도 건이 다른 알림 뒤로 밀리지 않는 것이다. 다른 알림 뒤로 밀리면 선행 알림이 후속 알림 종료 시까지 완료되지 않아 알림 간 완료 순서가 깨진다. 단일 알림 내에서의 발송 위치는 중요하지 않으며(수신자 중 누군가는 10만 번째로 수신함), 기존 순번을 유지하면 재시도 시에도 정렬 키 값이 바뀌지 않아 단순하다.

## 검토한 대안

- **알림 간 교차 발송(Round-Robin)**: 후속 알림도 첫 발송이 즉시 시작되지만 두 알림 모두 완료 시점이 늦어진다. 장애 발생 시 두 알림이 함께 미완료 상태로 남으며, 알림별로 번갈아 점유하는 쿼리도 복잡해진다.
- **재시도 건을 전체 대기열의 맨 뒤로 이동**: 선행 알림의 재시도 건이 후속 알림 뒤로 밀려 알림 간 완료 순서가 깨진다.
