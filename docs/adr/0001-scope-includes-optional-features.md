# ADR-0001. 선택 구현(긴급 알림, 워커 다중화)을 처음부터 설계에 넣는다

## 배경

과제에는 필수 기능과 선택 기능이 있다. 선택 기능 중 긴급 알림과 워커 다중화는 나중에 덧붙이기 어려운 종류다. 시스템의 뼈대를 바꾸기 때문이다.

## 결정

긴급 알림과 워커 다중화를 처음부터 설계에 넣는다. 구현 순서는 필수 기능, 워커 다중화, 긴급 알림이다. 기한이 모자라면 긴급 알림만 README에 설계 의도로 남긴다.

## 이유

- 워커가 여러 대면 정할 것이 많다. 일을 어떻게 나눠 가지는지, 한 대가 죽으면 그 일을 누가 이어받는지, 초당 50건 제한을 어떻게 함께 지키는지가 모두 여기서 나온다.
- 긴급 알림은 대기열의 구조와, 무엇을 먼저 보낼지 정하는 방식을 바꾼다.
- 워커 한 대, 알림 한 종류를 전제로 만들면 나중에 이 뼈대를 다시 짜야 한다.

## 결과

둘 다 구현했다.
