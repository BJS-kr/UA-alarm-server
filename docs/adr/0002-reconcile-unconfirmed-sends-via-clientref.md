# ADR-0002. 보냈는지 모르는 건은 clientRef로 조회한 뒤에만 다시 보낸다

## 배경

외부 발송 API는 중복을 막아 주지 않는다. 같은 요청을 두 번 보내면 수신자는 두 번 받는다.

그런데 "보냈는지 모르는" 경우가 생긴다. 예를 들어 요청을 보냈는데 10초 안에 답이 없으면, 외부가 접수했는지 아닌지 우리는 알 수 없다. mock은 일부 요청(약 2%)을 접수만 하고 30초 동안 답하지 않는다. 이런 건을 그냥 다시 보내면 중복이 되고, 보낸 것으로 치면 누락이 될 수 있다.

## 결정

보냈는지 모르는 건은 결과 미확정(UNCONFIRMED)으로 둔다. 그리고 외부의 발송 내역을 `GET /v1/messages?clientRef=`로 조회한다.

- 기록이 있으면 발송 완료(SENT)로 확정한다.
- "기록 없음"이라는 답을 받았을 때만 다시 보낸다.
- 조회 자체가 실패하면 다시 보내지 않고, 조회만 다시 한다.

clientRef는 우리가 요청마다 붙이는 꼬리표다. 외부는 이 값을 저장해 두고, 이 값으로 발송 내역을 찾아 준다.

## 언제 "보냈는지 모른다"인가

| 상황 | 판단 |
| --- | --- |
| 202 | 보냈다. 완료 |
| 400 | 외부가 거절했다. 실패로 확정 |
| 429, 500, 503, 요청이 나가기 전의 연결 오류 | 보내지 않았다. 다시 보내도 중복이 아니다. 처리는 ADR-0014 |
| 타임아웃(10초), 요청을 보낸 뒤 연결이 끊김, 502·504, 해석할 수 없는 2xx | 모른다. 결과 미확정 |
| 워커가 결과를 적지 못한 채 기한이 지남(ADR-0004) | 모른다. 넘겨받은 워커가 결과 미확정으로 둔다 |

요청이 나갔는지를 가르는 기준은 ADR-0037에 있다.

## 세부

- **clientRef는 `{alarmId}:{recipientId}`로 고정한다.** 다시 보내도 값이 같다. 그래서 조회 한 번으로 이전 시도가 모두 보인다.
- **조회는 이전 시도가 더는 보낼 수 없게 된 때부터 5초 뒤에 한다.** 그때는 타임아웃을 처리한 시각이거나, 다른 워커가 넘겨받은 시각이다. 시도를 시작한 시각을 기준으로 삼지 않는 이유는, 멈췄다 깨어난 워커가 늦게 보낼 수 있기 때문이다(ADR-0004). 너무 일찍 조회하면 아직 기록이 없어 "없음"이 나오고, 그 재발송이 중복이 된다.
- **다시 보낼 건은 대기(PENDING)로 돌린다.** 그 자리에서 바로 보내지 않는다. 다시 보낼 때도 토큰(ADR-0009)과 우선순위 순서(ADR-0011)를 똑같이 지키기 위해서다.
- **HTTP 타임아웃은 10초다.** mock의 느린 응답(실측 3~4.5초)은 기다려서 받고, 30초 동안 답하지 않는 요청은 끊는다. 조회에도 따로 10초 한도를 둔다.

## 5초의 근거

- mock을 재 보니, 30초 동안 답하지 않는 요청도 느린 요청도 접수하는 즉시 기록했다([mock-observations.md](../mock-observations.md)).
- 남긴 5초는, 끊기 직전에 보낸 요청이 네트워크를 건너 도착하는 여유다.
- 이 5초는 ADR-0004의 드문 틈(발송 직전 확인을 통과한 직후 워커가 멈춤)에 대한 완충도 된다. 그 틈에서 중복이 나려면 워커가 15초 넘게 멈춰 있어야 한다.
- 설정값(`RECONCILE_DELAY_MS`)이다. 외부 서비스가 바뀌면 그 서비스가 기록을 남기는 데 걸리는 시간을 재서 다시 정한다.

## 검토한 후보

- **응답을 끝까지 기다림(타임아웃을 30초보다 길게)**: 단순하다. 하지만 워커가 죽은 건은 어차피 조회가 필요해서 처리 경로가 둘이 된다. 실제 외부 서비스가 얼마나 늦게 답할지도 알 수 없다.
- **타임아웃이면 바로 재시도**: 중복 발송이 된다.
- **타임아웃이면 보낸 것으로 침**: 요청이 닿지 않은 경우 누락이 된다.
- **시도마다 clientRef에 번호를 붙임**: 조회할 값이 시도 수만큼 늘어난다.
- **조회를 30초 기다림**: 외부가 기록을 늦게 남기는 경우까지 덮는다. 하지만 mock은 접수 즉시 기록하므로, 결과 확정만 25초 늦어진다.
