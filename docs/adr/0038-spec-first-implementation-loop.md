# ADR-0038. 요구사항-설계-테스트 추적성 매트릭스 및 명세 기준 검증

## 배경

기능 및 비기능 요구사항이 다수의 아키텍처 결정(ADR)과 테스트 계층에 걸쳐 구현되므로, 설계와 구현이 진행되면서 초기 요구사항이 누락되거나 요구사항에 없는 불필요한 구현이 추가될 위험이 있다.

## 결정

원본 과제 명세를 최상위 기준으로 삼고, 요구사항부터 ADR 및 테스트 케이스까지 양방향으로 추적 가능한 매트릭스를 유지하며 반복 검증한다.

## 상세

### 우선순위 체계

```
과제 명세 > ADR > CONTEXT.md > 세부 구현
```

설계 문서(ADR)가 명세와 상충하는 경우 명세를 우선하며 설계를 수정한다.

### 요구사항부터 테스트까지의 추적성

```
명세 요구사항(R·O·S ID) → ADR → 시스템 불변식(보장) → 검증 테스트
```

[requirements.md](../requirements.md)를 통해 모든 필수(`R`)·선택(`O`)·제출(`S`) 요구사항을 대응 ADR과 테스트 파일에 연결한다. 연결된 ADR이나 테스트가 없는 요구사항은 미구현 항목으로, 어떤 요구사항에도 연결되지 않는 구현은 범위 초과로 식별한다.

### 원본 명세의 비공개 관리

과제 원본 문서는 외부 공개 및 제3자 공유가 금지된 자료이므로 `.gitignore`로 제외된 로컬 경로(`.local/`)에만 보관한다. 저장소에 커밋되는 문서에는 자체 문장으로 요약한 요구사항 대응표([requirements.md](../requirements.md))만 포함하며 원본 명세 문장을 그대로 전재하지 않는다.
