# ADR-0028. 로그는 표준 출력 JSON으로 쓰고, debug는 생략 없이 남기며, 비밀정보는 가린다

## 결정

- NestJS 기본 로거(`ConsoleLogger`)의 JSON 모드로 표준 출력에 쓴다. NestJS 11부터 기본으로 되므로 pino 같은 의존성이 필요 없다(ADR-0005).
- 기본 로거를 얇게 감싸서, `AsyncLocalStorage`에 담긴 traceId, alarmId, deliveryId를 모든 줄에 자동으로 붙인다.
- 로그 파일은 만들지 않는다. 수집은 플랫폼에 맡긴다.
- 비밀정보는 로거 한 곳에서 가린다. 부르는 쪽에서 빠뜨릴 수 없게 하기 위해서다.
- 로그 메시지와 오류 메시지(예외, API 오류 응답, 입력 검증 사유)는 영어로 쓴다. 로그 수집·검색 도구와 외부 연동에서 다루기 쉽고, 운영자가 그대로 검색어로 쓸 수 있다. 코드 주석과 문서는 한국어다.

## 수준별 내용

| 수준 | 내용 |
| --- | --- |
| info | API 요청 한 줄(메서드, 경로, 상태, 걸린 시간), 알림의 큰 사건(시작, 펼치기 완료, 취소, 완료) |
| warn | 일시 오류 뒤 재시도, 결과 미확정, 429, 넘겨받기 |
| error | 재시도를 다 쓴 실패, 중복 탐지, 서킷 브레이커 발동, 펼치기가 멈춤 |
| debug | 발송 시도마다 한 줄: alarmId, deliveryId, recipientId, 시도 번호, 요청 내용(가림), 응답 상태, messageId, 걸린 시간, 판정 |

- info 이상에서는 성공 건을 남기지 않는다. 성공 여부, 시각, messageId는 Delivery에 남으므로, 대량 알림 하나에 10만 줄이 같은 내용을 되풀이하지 않게 한다.
- debug는 Delivery와 겹치는 정보라도 생략 없이 모두 남긴다. `LOG_LEVEL=debug`로 켠다.

## 가리기(마스킹)

비밀정보는 통째로 빼지 않고 가린다. 디버깅에 필요한 맥락은 남기기 위해서다.

| 대상 | 방식 |
| --- | --- |
| 본문 | 네 자리 이상 이어진 숫자를 같은 길이의 `*`로 바꾼다(인증번호, 카드번호 등) |
| 전화번호 | 가운데 자리를 가린다(`010-****-2749`) |
| 비밀 키(password, token, authorization, apiKey 등) | 전부 가린다 |
| 접속 주소의 비밀번호(`user:pw@host`) | 필드 이름과 관계없이, 모든 문자열에서 비밀번호만 가린다 |
| 오류의 글(message, stack, detail, cause) | 필드 이름과 관계없이 네 자리 이상 숫자와 접속 주소의 비밀번호를 가린다. 스택의 호출 위치 줄과 오류 코드(`code`, `errno` 등)는 그대로 둔다 |

- **오류는 내용으로 가린다.** 오류의 글은 우리가 쓰지 않는다. DB 드라이버와 Drizzle은 실패한 문장의 값을 message나 detail에 담으므로(예: `params: …`, `Failing row contains (…)`), 본문과 수신자가 필드 이름 없이 섞여 들어온다.
- **로그 메시지도 같은 방식으로 가린다.** 우리 메시지는 숫자가 없는 상수라 바뀌지 않고, 오류를 첫 인자로 넘기면 그 오류의 글이 메시지가 되기 때문이다.
- 전화번호는 발송에 필요 없으므로 DB에 저장하지 않는다.

## 수집

표준 출력 JSON까지만 책임진다. 이 형식은 Docker 로그 드라이버, Fluent Bit, Loki, CloudWatch 등이 공통으로 받으므로 코드를 바꾸지 않고 붙일 수 있다. 평가와 개발 중에는 `docker compose logs`로 보고 deliveryId 등으로 검색한다.

## 검토한 후보

- **pino(nestjs-pino)**: 더 빠르지만, 로그량이 초당 수백 줄 수준이라 기본 로거로 충분하다.
- **비밀정보가 든 필드를 통째로 생략**: 디버깅에 필요한 맥락까지 사라진다.
- **성공 건도 info로 기록**: Delivery와 같은 내용이 알림마다 10만 줄씩 되풀이된다.
