# ADR-0005. 의존성은 의도적으로 최소화한다

## 결정

이 프로젝트의 설계 원칙이다. 새 구성 요소(인프라, 라이브러리, 간접 계층)는 이미 쓰는 것(OS, PostgreSQL, Node.js 표준 기능, NestJS)으로 해결할 수 없을 때만 추가한다. 흔한 도구를 몰라서 빼는 것이 아니다. 그 도구가 주는 기능을 하나씩 확인하고, 각각을 이미 가진 것으로 대신할 수 있을 때 뺀다.

## 이유

- 구성 요소가 하나 늘 때마다 장애 지점, 운영 대상(설정, 백업, 모니터링, 장애 조치), 시스템끼리 상태가 엇갈릴 가능성이 함께 는다.
- 동시성과 장애 처리가 맞는지는 "무엇을 끝까지 믿는가"로 정해진다. 믿는 대상이 하나면 판단끼리 다툴 일이 없다.
- 이미 쓰는 시스템이 보장하는 성질에 기대면 따로 증명할 것이 적다. 예를 들어 Postgres는 행 잠금으로 같은 행의 조건부 UPDATE를 한 번에 하나씩 처리하고, `SKIP LOCKED`로 같은 행을 두 워커에 주지 않는다.

## 적용 방법

- 흔한 대안을 기각할 때는 그 도구가 주는 기능과 우리가 대신 쓰는 수단을 나란히 적는다(예: ADR-0003의 BullMQ 대응표).
- 결정마다 "다시 볼 조건"을 적는다. 최소화는 고집이 아니라 지금 규모에 맞춘 선택이며, 조건이 바뀌면 구성 요소를 추가한다.

## 실제로 추가한 의존성

| 의존성 | 이유 |
| --- | --- |
| `drizzle-orm`, `pg` (개발: `drizzle-kit`) | DB 접근과 마이그레이션(ADR-0036) |
| `@nestjs/config`, `class-validator`, `class-transformer` | 설정과 입력 검증(ADR-0030, 0037) |
| `@nestjs/swagger` | OpenAPI 문서(ADR-0037) |
| `prom-client` | Prometheus 메트릭(ADR-0027) |
| 개발: Jest, Stryker, ESLint, Prettier | 테스트와 변이 테스팅(ADR-0034, 0035), 코드 형식 |

## 검토한 후보

- **기능마다 검증된 전용 도구(BullMQ, Redis 기반 rate limiter 등)**: 직접 짤 코드는 줄지만 상태가 여러 시스템에 흩어진다. 이 과제의 핵심인 중복과 누락 방지가 시스템 사이의 동기화 문제로 바뀐다.
