# ADR-0022. 알림 생성의 중복 요청은 막지 않는다

## 배경

응답을 못 받은 클라이언트는 생성 요청을 다시 보낼 수 있다. 그러면 같은 내용의 알림이 두 개 생긴다. 결제 API처럼 요청 한 번이 곧 실행인 경우에는, 이런 중복을 `Idempotency-Key` 헤더로 막는 것이 흔하다.

## 결정

알림 생성의 중복은 따로 막지 않는다.

## 이유

- **생성만으로는 아무것도 나가지 않는다.** 발송은 특정 ID에 대한 시작 요청으로만 일어나고, 그 요청은 상태로 중복이 걸러진다(ADR-0016). 생성 중복의 결과는, 보내지 않은 초안이 하나 더 남는 것뿐이다.
- **남은 초안은 정리하기 쉽다.** 클라이언트가 조회해서 취소하면 된다.
- 생성과 발송을 나눈 설계 덕분에 막을 필요가 없어졌다.

## 검토한 후보

- **`Idempotency-Key` 헤더**: 키 저장 테이블, 만료 처리, 같은 키에 다른 내용이 왔을 때의 규칙이 생긴다. 그에 비해 막아 주는 피해가 거의 없다.
