# 알림 생성의 중복 요청은 막지 않는다

응답을 못 받은 클라이언트가 생성 요청을 다시 보내면 같은 내용의 알림이 두 개 생긴다. 이를 따로 막지 않는다.

- 생성만으로는 아무것도 발송되지 않는다. 발송은 특정 ID에 대한 시작 요청으로만 일어나고, 그 요청은 상태 기준으로 중복이 걸러진다(ADR-0016). 생성 중복의 결과는 보내지 않은 초안이 하나 더 남는 것뿐이다.
- 남은 초안은 클라이언트가 조회하고 취소하면 되므로 후처리가 어렵지 않다. 이 정도는 사용자의 몫으로 둔다.
- 생성과 발송을 분리한 설계 덕분에 막을 필요가 없어졌다.

## 검토한 후보

- **`Idempotency-Key` 헤더**: 요청 한 번이 곧 실행인 API(결제 등)에는 필요하지만, 여기서는 키 저장 테이블, 만료 처리, 같은 키에 다른 내용이 왔을 때의 규칙이 생기는 데 비해 막아 주는 피해가 거의 없다.
