# 모든 워커 종료는 "반납"과 "잠금 해제" 두 출구로 수렴한다

워커가 내려가는 경우는 배포, 축소, 크래시, OOM, 멈춤, 네트워크 분리 등 여러 가지지만, 쥐고 있던 건을 처리하는 출구는 둘뿐이다. 정상 종료가 끝까지 성공하면 워커가 쥐고 있던 건을 직접 반납한다. 그 밖의 모든 경우는 잠금이 풀리고 다른 워커가 넘겨받는다(ADR-0004).

넘겨받기는 "누가, 왜 끝냈는가"가 아니라 "잠금이 풀렸다"는 사실로만 일어난다. 그래서 종료시키는 주체(워커 자신, 다른 워커의 무효 선언, 플랫폼, 운영자)와 복구 경로가 분리된다.

## 출구 1: 정상 종료 (SIGTERM)

배포, 워커 수 축소, 운영자 정지, 호스트 재부팅, 쿠버네티스 롤링 업데이트·drain처럼 종료를 요청받는 경우다.

```
SIGTERM
 → 새 Delivery를 꺼내지 않는다 (펼치기 중이면 현재 페이지를 커밋하고 멈춘다)
 → 이미 보낸 요청의 응답을 기다려 결과를 기록한다 (최대 HTTP 타임아웃 10초)
 → 꺼냈지만 보내지 않은 Delivery는 대기 상태로 되돌린다 (확실히 안 보냈으므로 즉시 안전)
 → 잠금 연결을 닫고 종료한다
```

- 배포 때마다 일어나는 일이다. 이 경로가 없으면 배포할 때마다 쥐고 있던 건이 전부 결과 미확정이 되어 대기와 조회를 거친다.
- `stop_grace_period: 30s`로 둔다. Docker 기본값 10초는 HTTP 타임아웃과 같아 마무리가 잘릴 수 있다.
- 유예 시간을 넘기면 Docker가 SIGKILL을 보내고 출구 2로 합류한다.
- 신호가 Node 프로세스까지 도달해야 한다. `npm start`나 셸 형식 `CMD`는 신호를 전달하지 않으므로 exec 형식(`CMD ["node", "dist/main-worker.js"]`)과 compose의 `init: true`를 쓴다.

## 출구 2: 잠금 해제 (그 밖의 모든 경우)

```
[워커가 무효해짐]
 ├ 크래시, OOM, docker kill                      → 프로세스가 죽어 세션이 끝남
 ├ DB 연결 끊김                                  → 세션이 끝남 (워커는 스스로 종료)
 └ 15초 넘게 응답 없음                            → 다른 워커가 그 워커의 세션을 강제 종료
   (이벤트 루프 막힘, 긴 GC, docker pause, SIGSTOP)
        ↓
 Postgres가 잠금 해제
        ↓
 다른 워커가 owner 없음을 확인하고 넘겨받음
        ↓
 넘겨받은 시각 + 5초 → clientRef 조회 → 완료 확정 또는 재발송 (ADR-0002)

 무효가 된 워커가 살아 있었다면 → 발송 직전 확인에서 걸려 종료
 종료된 컨테이너 → restart 정책이 새 ID로 새 워커를 띄움
```

## 생존 관련 장치 정리

| 장치 | 누가 | 하는 일 |
| --- | --- | --- |
| 생존 신호 (2초마다 `SELECT 1`) | 워커 자신 | DB에 마지막 활동 시각을 남긴다 |
| 무효 선언 (15초) | 살아 있는 다른 워커 | DB에서 조용한 워커를 찾아 그 세션을 강제 종료한다 |
| 발송 직전 확인 (5초) | 워커 자신 | 잠금 연결이 살아 있음을 확인하지 못하면 종료한다 |
| healthcheck / liveness probe | 플랫폼 | 얼어붙은 컨테이너를 재시작한다 (일손 보충, 정확성과 무관) |

Postgres의 TCP keepalive는 끊긴 연결을 정리할 뿐이며, 얼어붙은 프로세스는 커널이 응답하므로 잡지 않는다. 얼어붙은 워커는 무효 선언이 잡는다.

## 얼어붙은 컨테이너의 재시작

정확성은 무효 선언이 지키므로, 얼어붙은 컨테이너를 재시작하는 일은 일손을 되찾는 문제일 뿐이다. 애플리케이션은 판단 재료(healthcheck)만 제공하고 컨테이너를 죽일 권한은 갖지 않는다. healthcheck 방식은 운영 결정에서 정한다.

- **docker compose (제출 환경)**: healthcheck는 컨테이너를 unhealthy로 표시만 하고 재시작하지 않는다. 운영자가 재시작할 때까지 워커 한 대만큼 일손이 줄어든 채로 계속 발송한다.
- **쿠버네티스 (운영 환경 가정)**: liveness probe가 실패하면 kubelet이 컨테이너를 재시작한다.

## 검토한 후보

- **compose 환경에 자동 재시작 도구(autoheal 등) 추가**: unhealthy 컨테이너를 재시작하려면 `docker.sock`이 필요하다. 호스트 root 권한을 가진 컨테이너와 의존성이 하나 늘어나므로(ADR-0005) 두지 않는다.
