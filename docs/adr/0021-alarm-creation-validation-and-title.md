# ADR-0021. 알림 생성 입력 검증 규칙 및 title 필드의 관리용 한정 사용

## 배경

알림 생성 API는 단일 요청으로 최대 10만 명의 수신자에게 발송될 알림을 정의한다. 필수 필드 누락이나 필드명 오타로 인해 의도치 않은 전체 발송이 발생하는 사고를 방지해야 한다. 또한 외부 발송 API 스키마에는 `body`만 존재하고 `title` 필드가 없으므로 `title`의 처리 방침을 정의해야 한다.

```json
POST /v1/alarms
{ "type": "URGENT", "title": "결제 안내", "body": "결제가 완료되었습니다.", "recipientIds": ["u_000001"] }
```

## 결정

### 1. 오발송 방지를 위한 구조 검증

- **`type`은 필수이며 기본값을 두지 않는다**: 기본값을 `BULK`로 설정할 경우 필드 누락만으로 10만 명 대상 알림이 생성된다.
- **정의되지 않은 필드가 포함되면 `400`으로 거절한다**: `recipientIDs` 같은 필드명 오타를 무시하면 클라이언트는 수신자를 지정했다고 가정하나 서버는 수신자 미지정으로 처리하게 된다.
- **`BULK` 알림에 `recipientIds`가 포함되면 거절한다**: 특정 수신자 지정 의도와 전체 발송 타입이 충돌하는 요청을 차단한다.

### 2. 필드별 값 검증

| 필드                                 | 검증 규칙                                       |
| ------------------------------------ | ----------------------------------------------- |
| `title`                              | 1~100자, 공백 문자로만 구성된 값 거절           |
| `body`                               | 1~1000자, 공백 문자로만 구성된 값 거절          |
| `recipientIds` (`URGENT` 전용, 필수) | 1~100개, 각 요소 1~64자, 중복 요소 포함 시 거절 |

- **문자열 길이는 유니코드 코드 포인트 수를 기준으로 계산한다**: PostgreSQL의 `CHECK (char_length(...))` 제약 조건과 동일한 기준을 적용하여, 애플리케이션 검증을 통과한 입력이 DB 저장 단계에서 거절되지 않도록 보장한다.
- **NUL 문자(`U+0000`)가 포함된 문자열은 거절한다**: PostgreSQL `text` 타입에 저장할 수 없어 `500` 오류가 발생하므로 입력 단계에서 차단한다. 수신자 목록 조회의 커서 파라미터에도 동일하게 적용한다.
- **중복 수신자 ID는 자동 제거하지 않고 거절한다**: 중복 입력은 클라이언트 측 버그의 신호이므로 명시적으로 오류를 반환한다.
- **수신자 실존 여부는 생성 시점에 검증하지 않는다**: 외부 사용자 API가 단건 조회 기능을 제공하지 않아 확인 시 전체 사용자를 페이지 단위로 순회해야 한다. 존재하지 않는 수신자는 발송 시점에 `UNKNOWN_RECIPIENT` 사유로 실패(`FAILED`) 처리되어 Delivery에 기록된다.

### 3. `title` 필드의 용도 (요구사항 해석)

외부 발송 API 스키마에는 `body` 필드만 존재하고 `title` 필드가 없다. 외부 연동 계약에 없는 필드를 서버가 임의로 `body`에 결합하지 않고 발송 시에는 `body`만 전달하며, `title`은 알림 목록 및 단건 조회에서 알림을 식별하는 관리용 이름으로만 사용한다. 이 해석은 README에 명시한다.

## 검토한 대안

- **제목과 본문을 결합해 발송(`[제목] 본문`)**: 메시지 포맷을 서버가 임의로 변경하게 되며 제목이 불필요한 알림(인증번호 안내 등)에도 강제로 결합된다.
- **`type` 기본값을 `BULK`로 지정**: 필드 누락 시 전체 발송으로 이어질 위험이 있다.
- **중복 수신자 자동 병합**: 클라이언트의 요청 생성 오류를 은폐한다.
- **`class-validator`의 `@Length` 데코레이터 사용**: 이모지 변형 선택자(`U+FE0F`)를 길이 계산에서 제외하여 DB `char_length`와 기준이 불일치한다. 예를 들어 `❤️` 51개(코드 포인트 102개)를 100자로 통과시켜 DB 제약 조건 위반으로 `500` 오류가 발생한다.
