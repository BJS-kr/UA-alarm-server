# ADR-0008. 알림 상태는 5단계로 정의하며 발송 중 취소는 CANCELING을 거친다

## 배경

수신자 10만 명 규모의 대량 알림은 발송 시작부터 종료까지 30분 이상 진행 상태로 유지된다. 그 사이 알림이 취소될 수 있고 일부 수신자 발송은 실패할 수 있으므로, 알림 상태 모델은 진행 단계와 최종 확정 여부를 명확히 나타내야 한다.

## 결정

```
CREATED ──발송 시작──▶ SENDING ──모든 Delivery 종료──▶ COMPLETED
   │                      │
   │ 취소                  │ 취소 요청, 또는 수신자 조회의 영구 오류
   ▼                      ▼
CANCELED ◀──남은 건 정리── CANCELING
```

| 상태        | 의미                                                             |
| ----------- | ---------------------------------------------------------------- |
| `CREATED`   | 알림이 생성되었으나 아직 발송이 시작되지 않은 상태               |
| `SENDING`   | 발송 진행 중인 상태                                              |
| `CANCELING` | 신규 발송은 중단되었고, 이미 전송된 요청의 결과를 정리 중인 상태 |
| `CANCELED`  | 취소 처리가 완료되어 집계 건수가 더 이상 변하지 않는 상태        |
| `COMPLETED` | 모든 `Delivery`가 발송 성공 또는 실패로 종결된 상태              |

- **발송 중(`SENDING`)인 알림을 취소하면 `CANCELING`이 된다.** 신규 발송 점유는 즉시 중단되며, 이미 전송된 요청과 결과 미확정(`UNCONFIRMED`) 건이 모두 정리되면 `CANCELED`로 전환된다.
- **발송 시작 전(`CREATED`) 알림은 취소 시 즉시 `CANCELED`가 된다.** 전송된 요청이 없기 때문이다.
- **시스템도 알림을 `CANCELING`으로 전환할 수 있다.** 수신자 목록 조회가 영구 오류(비재시도성 오류: `400`, `401`, `403`, `404`)로 실패한 경우다(ADR-0006). 취소 전환 주체와 원인은 취소 사유(`REQUESTED`, `EXPANSION_FAILED`)로 구분한다(ADR-0017).
- **일부 `Delivery`가 실패해도 알림 상태는 `COMPLETED`가 된다.** 세부 결과는 성공 및 실패 건수로 제공한다.
- **`COMPLETED`와 `CANCELED`는 종결(terminal) 상태다.** 이후 상태와 집계 건수가 더 이상 변경되지 않는다.

## 근거

취소 시점에 이미 전송된 요청은 되돌릴 수 없다. 취소 요청 즉시 `CANCELED`로 전환하면, 이후 도착하는 응답이나 상태 확정(Reconciliation) 결과로 인해 취소된 알림의 건수가 계속 변동된다. `CANCELING`을 거치면 `CANCELED`가 된 이후에는 집계 건수가 고정된다.

## 검토한 대안

- **취소 요청 시 즉시 `CANCELED`로 전환**: 취소 완료 후에도 건수가 계속 바뀌어 상태와 집계 숫자가 불일치한다.
- **부분 실패 상태(`PARTIALLY_FAILED` 등) 도입**: 수신 거부 사용자가 약 1%이므로 거의 모든 대량 알림이 이 상태가 되어 상태값이 유의미한 정보를 주지 못한다.
