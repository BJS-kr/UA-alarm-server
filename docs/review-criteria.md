# 독립 심사 기준

구현 완료 후 새로운 컨텍스트에서 실행되는 검증 에이전트용 심사 기준 문서다.

## 심사 원칙

심사의 기준은 원본 과제 명세(`.local/assignment.md`)다. 저장소 내 설계 문서(ADR, README, `docs/requirements.md`)는 검증 대상 주장으로 취급하며, 구현과 문서가 명세 요구사항을 실질적으로 충족하는지 코드 및 실행 결과로 확인한다.

- 명세 요구사항의 충족 여부를 실제 테스트 및 스크립트 실행으로 검증한다.
- 외부 API 특성, 처리 규모, 운영 환경 가정에 비추어 설계 결정의 타당성을 검토한다.
- 문서에 기술된 보장(중복·누락 방지, 장애 복구, 처리량 제한, 긴급 알림 우선 처리, 취소 정합성)이 실제 코드와 일치하는지 대조한다.
- 명세의 모호한 영역에 대한 해석이 합리적인지 확인한다.

## 입력 자료

- 원본 과제 명세: `.local/assignment.md`
- 저장소 전체 코드 및 문서

## 검증 절차

### 1. 명세 기반 체크리스트 도출

저장소 내 문서를 읽기 전에 원본 명세만을 기준으로 핵심 검증 항목과 엣지 케이스 목록을 먼저 작성한다.

### 2. 코드 검토 및 실행 검증

도출한 체크리스트를 코드와 실행 결과로 검증한다.

기본 실행 검증 항목:

- `docker compose --profile test run --rm test` (빌드, 린트, 단위·통합 테스트)
- `docker compose up` 기동 후 전체 컨테이너 `healthy` 상태 도달 여부
- `bash scripts/e2e.sh` (수신자별 정확히 1회 발송 및 `429` 미발생 확인)
- `docker compose --profile test run --rm test npm run test:mutation` (변이 점수 및 생존 변이 확인)
- `docker compose --profile test run --rm test npm run test:sabotage` (전체 결함 주입 검출 여부 확인)

### 3. 문서 정합성 검증

`README.md`, `docs/requirements.md`, `docs/adr/*`, `CONTEXT.md`를 검토한다.

- 각 ADR의 근거가 명세 조건에 부합하는지 확인한다.
- 문서에 기술된 동작과 수치가 실제 코드 및 실측 결과와 일치하는지 확인한다.
- `README.md`가 제출 필수 포함 항목(실행·테스트 방법, API 요청·응답 예시, 설계·구현 코멘트, 미구현 영역 설계 의도, 명세 해석)을 누락 없이 포함하는지 확인한다.

### 4. 테스트 공백 검토

통과하는 테스트가 실제로 불변식을 검증하는지, 누락된 경쟁 조건이나 타이밍 의존 검증이 없는지 확인한다.

### 5. 준수 규칙 확인

- `CLAUDE.md`에 승인된 목록 외의 외부 의존성이 추가되지 않았는지 확인한다.
- 원본 명세의 문장이 커밋 대상 파일에 그대로 복사되지 않았는지 확인한다(ADR-0038).

## 보고 형식

각 지적 사항은 다음 항목을 포함한다.

- **심각도**: `차단`(명세 위반, 중복·누락 가능성, 실행 실패, 코드-문서 불일치) / `개선` / `참고`
- **근거**: 관련 요구사항 ID(`docs/requirements.md`) 및 ADR 번호
- **위치**: `파일 경로:줄 번호`
- **증거**: 재현 명령 및 출력 또는 코드 인용
