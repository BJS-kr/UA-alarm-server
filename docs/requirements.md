# 요구사항 대응표

과제 명세의 요구사항을 우리 말로 요약하고, 각 요구사항을 다루는 결정(ADR)과 그것을 지키는 테스트를 잇는다. 원본 명세는 비공개라 저장소에 두지 않는다(ADR-0038). 테스트 열은 구현하면서 채운다.

심사는 이 표의 왼쪽(요구사항)에서 출발해 오른쪽으로 따라간다. 연결된 ADR이 없는 요구사항은 빠뜨린 것이고, 어떤 요구사항에도 연결되지 않는 구현은 범위를 넘은 것이다.

## 명세 해석

| 모호한 점 | 해석 | ADR |
| --- | --- | --- |
| 외부 발송 API에 제목 필드가 없다 | 본문만 보내고, 제목은 알림을 구별하는 관리용 이름으로 쓴다 | 0021 |
| "발송 완료"의 기준 | 외부 API가 202로 접수했거나, 발송 내역 조회로 기록이 확인된 것 | 0002, 0032 |
| "중복 없음"의 기준 | 한 알림에서 수신자마다 외부 발송 기록이 정확히 한 번 남는다 | 0002, 0035 |
| "전체 사용자"를 정하는 시점 | 발송을 시작할 때 사용자 API를 끝까지 읽은 결과 | 0006 |
| 같은 내용을 다시 보내는 경우 | 새 알림을 만든다. 알림은 발송 한 번의 단위다 | 0023 |
