# 테스트 전략 및 검증 결과

테스트 품질은 단순 라인 커버리지가 아니라 각 ADR에 정의된 시스템 불변식 보장 여부로 평가한다(ADR-0034). 테스트는 단위·통합·E2E 3개 계층으로 구성하며, DB 연동은 항상 실제 PostgreSQL을 사용한다(ADR-0035).

## 실행 명령

호스트 환경에는 Docker만 설치되어 있으면 된다.

```bash
docker compose --profile test run --rm test                              # ESLint + Prettier + 단위·통합 테스트
docker compose --profile test run --rm test npm run test:mutation        # Stryker 변이 테스팅
docker compose --profile test run --rm test npm run test:sabotage        # 결함 주입(Sabotage) 테스트
bash scripts/e2e.sh                                                      # E2E: mock 연동, 워커 3대(정상 종료 1, 강제 종료 1), 긴급 우선, 발송 중 취소
bash scripts/e2e-faults.sh                                               # E2E 장애 주입: mock 일시 정지, 워커 일시 정지, DB 재시작
```

## 테스트 계층 및 범위

| 계층               | 검증 대상                                                                                                                                                                                                                                                    | 경로                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| 단위 (Unit)        | 발송·조회 응답 분류, 재시도 정책·서킷 브레이커, 상태 전이표, 커서 인코딩, 설정 불변식 검증, 민감정보 마스킹, 추적 ID 파싱, HTTP 클라이언트 응답 분류 및 소켓 쓰기 직전 리스 검증, 관리 포트, 발송 시작·취소 응답 판정, 405·415 미들웨어                      | `test/unit`                   |
| 통합 (Integration) | REST API, `Delivery` 점유 순서 및 동시성, 공유 토큰 버킷, 완료 판정, 2단계 취소, 펜싱, 워커 전체 루프(장애 주입 포함), 우선순위, 처리량 제어, 수신자 확장 재개, 정상 종료(`SIGTERM`), 내역 조회 대기, 서킷 브레이커, 워커 프로세스 장애(`SIGKILL`·`SIGSTOP`) | `test/integration`            |
| E2E                | 실제 mock 컨테이너(사용자 2,000명, `/_admin/stats` 활성화) 연동. 워커 정상·강제 종료, 긴급 알림 우선 발송, 발송 중 취소, 외부 API·워커·DB 장애 주입 시나리오                                                                                                 | `scripts/e2e*.sh`, `test/e2e` |

통합 테스트는 테스트 파일마다 독립된 데이터베이스를 생성하며, 외부 API는 동일한 계약을 따르면서 응답 지연·실패를 제어할 수 있는 Fake HTTP 서버(`test/integration/support/fake-external-api.ts`)를 사용한다. E2E 테스트는 내부 DB 상태뿐 아니라 mock 서버의 `/_admin/stats` 집계를 대조하여 실제 중복 및 누락 여부를 검증한다.

## 결함 주입(Sabotage) 검증

핵심 동시성·장애 복구 장치가 실제로 동작하는지 확인하기 위해, 각 장치가 존재할 때 통과하는 테스트가 해당 장치를 코드에서 제거(결함 주입)했을 때 실제로 실패하는지 검증한다(`test/sabotage/sabotages.mjs`).

### 미검증 영역 및 한계

- 워커 루프 30초 무응답 시 컨테이너 오케스트레이터에 의한 자동 재시작 동작은 단위 테스트(관리 포트 `503` 반환 검증)까지만 확인했다.

## 생존 변이(Equivalent Mutants) 검토 내역

| 위치                  | 변이 내용                                            | 동등 변이 판정 근거                                                            |
| --------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| HTTP 클라이언트       | 기본 메서드 `'GET'`을 빈 문자열로 변경               | Node.js `http.request`가 빈 문자열을 기본값 `'GET'`으로 처리함                 |
| HTTP 클라이언트       | `status >= 200` 조건 제거                            | 최종 응답 핸들러에 1xx 상태 코드가 도달하지 않음                               |
| HTTP 클라이언트       | 내부 결과 태그 `kind: 'response'`를 빈 문자열로 변경 | 호출부에서 `kind === 'error'` 여부로만 분기함                                  |
| HTTP 클라이언트       | 중복 완료 가드 및 타이머 해제 제거                   | Promise는 단일 결정을 보장하며 완료된 요청의 `destroy()`는 무동작(no-op)임     |
| HTTP 클라이언트       | 응답 스트림 `error` 이벤트 분기                      | 응답 수신 도중 스트림 오류는 타임아웃과 동일하게 `unknown` 결과로 귀결됨       |
| HTTP 클라이언트·커서  | `catch` 블록 내 명시적 `return undefined` 제거       | 함수 종료 시 암묵적으로 `undefined`가 반환됨                                   |
| 민감정보 마스킹       | 재귀 깊이 제한 `> 6`을 `>= 6`으로 변경               | 순환 참조 방지 목적이 동일하게 유지됨                                          |
| 사용자 조회 오류 분류 | `status !== undefined` 조건 제거                     | `Set.has(undefined)`가 항상 `false`를 반환함 (타입 가드 목적 코드)             |
| 브레이커 판정 윈도우  | 시작 시각 비교 `>`를 `>=`로 변경                     | 단조 시계(`performance.now()`) 기반이라 동일 시작 시각 항목 간 순서만 영향받음 |
| HTTP 클라이언트       | 소켓 쓰기 직전 리스 만료 에러 상수·메시지 변경       | 내부적으로 동일 상수를 참조하며 에러 메시지는 외부로 노출되지 않음             |
