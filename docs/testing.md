# 테스트

테스트 품질은 커버리지가 아니라 "ADR의 보장을 지키는가"로 판정한다(ADR-0034). 층은 단위·통합·끝단 셋이며 DB는 항상 실제 PostgreSQL을 쓴다(ADR-0035).

## 실행

호스트에는 Docker만 있으면 된다.

```bash
docker compose --profile test run --rm test                              # 단위 + 통합
docker compose --profile test run --rm test npm run test:mutation        # 변이 테스팅
docker compose --profile test run --rm test npm run test:sabotage        # 고의 결함 목록
bash scripts/e2e.sh                                                      # 끝단(실제 mock, 워커 3대, 1대 강제 종료)
```

## 층과 대상

| 층 | 대상 | 파일 |
| --- | --- | --- |
| 단위 | 발송·조회 결과 분류, 재시도·브레이커, 전이표, 커서, 설정 관계 검증, 마스킹, 추적 ID, HTTP 클라이언트 분류, 관리 포트 | `test/unit` |
| 통합 | API, 꺼내기 순서와 동시성, 토큰 버킷, 완료 판정, 취소, 펜싱, 워커 전체 흐름(장애 주입), 우선순위, 처리량, 펼치기 재개, 정상 종료, 멈춘 워커의 무효 선언, SIGKILL 크래시 복구 | `test/integration` |
| 끝단 | 실제 mock 이미지(사용자 2000명), 워커 3대 중 1대를 발송 도중 `docker kill` | `scripts/e2e.sh`, `test/e2e` |

통합 테스트는 테스트 파일마다 새 DB를 만들고, 외부 API 자리에는 계약은 같고 동작을 미리 정할 수 있는 가짜 서버(`test/integration/support/fake-external-api.ts`)를 둔다.

## 최근 결과

| 항목 | 결과 |
| --- | --- |
| 단위 + 통합 | 135개 통과 (단위 93, 통합 42) |
| 변이 점수(Stryker) | 96.5% (기준선 90%) |
| 고의 결함 목록 | 16/16 검출 |
| 끝단 | 대량 2000건 + 긴급 4건, 워커 3대 중 1대 강제 종료: 중복 0, 누락 0, 429 0, 넘겨받기 5건 |
| 처리량 | 초당 49.1건 (상한 50, 429 0) |

## 변이 테스팅으로 드러난 것

첫 점수는 73.8%였다. 살아남은 변이를 보고 두 갈래로 고쳤다.

- **비어 있던 테스트를 채웠다.** 설정 관계의 경계값(같은 값이면 거부되는가), 재시도·브레이커 관계 검증, 추적 미들웨어, 마스킹 규칙별 동작, HTTP 클라이언트의 메서드·경로, keepAlive 재사용, 소켓 상한, 타임아웃 시 요청 끊기, `close()`의 소켓 정리, 200이 아니거나 JSON이 아닌 응답.
- **결과를 바꾸지 않는 코드를 지웠다.** class-transformer 기본값과 같은 옵션, 바로 뒤 조건과 겹치는 커서 검사, 쓰이지 않는 상수, 연결 단계 오류 코드 목록(ADR-0037의 "안 보냄" 판정을 하나로 줄였다), 이름 목록에 묶여 있던 URL 비밀번호 마스킹(모든 문자열로 넓혔다).

남은 생존 변이는 결과가 같은 변이로 판정해 받아들였다.

| 위치 | 변이 | 판정 |
| --- | --- | --- |
| HTTP 클라이언트 | 메서드 `'GET'`을 빈 문자열로 | Node가 빈 메서드를 GET으로 보낸다 |
| HTTP 클라이언트 | `status >= 200` 조건 제거 | 최종 응답으로 1xx가 오지 않는다 |
| HTTP 클라이언트 | 중복 완료 가드, 타이머 해제 제거 | Promise는 한 번만 끝나고, 끝난 요청의 destroy는 아무 일도 하지 않는다 |
| HTTP 클라이언트 | 응답 스트림 `error` 분기 | 응답 도중 스트림 오류를 결정적으로 재현할 수 없다. 재현되지 않으면 타임아웃 경로(같은 `unknown`)로 끝난다 |
| HTTP 클라이언트·커서 | `catch`의 `return undefined` 제거 | 함수가 어차피 undefined를 돌려준다 |
| 마스킹 | 깊이 제한 `> 6`을 `>= 6`으로 | 제한의 목적(순환 참조 차단)은 같다 |

## 고의 결함 목록으로 드러난 것

`test/sabotage/sabotages.mjs`에 ADR별로 깨뜨릴 SQL·로직과 실패해야 할 테스트를 둔다. 처음 실행에서 S01(꺼내기 정렬에서 우선순위 제거)을 놓쳤다. 테스트가 10건을 한 번에 꺼낸 뒤 순서를 봤는데, `claim()`이 반환 전에 JS에서 다시 정렬해 SQL 정렬이 깨져도 가려졌다. 우선순위의 의미는 "토큰 수(LIMIT)만큼 꺼낼 때 무엇을 고르는가"이므로 한 건씩 꺼내 고른 순서를 보도록 고쳤고, 이후 16/16을 검출한다.
